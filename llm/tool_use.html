ailia LLM Tool Use ガイド

ailia LLM で Gemma 4 の Function Calling（Tool Use）を使う方法を説明します。システムプロンプトでのツール定義、モデルの戻り値の形式、パース方法をまとめます。

概要

Gemma 4 は、ツール（関数）の宣言、ツール呼び出し、ツール実行結果を専用の制御トークンで表現するネイティブの Function Calling に対応しています。ailia LLM の API にはツール定義を渡す引数はありませんが、Gemma 4 の制御トークンはテキストとしてプロンプトに含めるだけで特殊トークンとしてトークナイズされるため、システムプロンプトにツール宣言を記述し、モデルの出力をアプリケーション側でパースすることで Tool Use を実現できます。

本ページの内容は Google の Gemma 4 Function Calling ドキュメント と、ailia LLM を使った実装例である ailia Insight の Agent モードに基づいています。

対応モデル

  • Gemma 4 E2B / E4B / 26B-A4B / 31B（GGUF）
注意: 制御トークンの形式は Gemma 4 固有です。他のモデルでは、そのモデルのチャットテンプレートが定義する形式に合わせる必要があります。

全体フロー

Tool Use は、モデルがツール呼び出しを出力し、アプリケーションがツールを実行して結果を返し、モデルが最終回答を生成する、というループで実現します。

システムプロンプト
ツールの説明 + 呼び出し形式の指示 + <|tool> 宣言
↓
ailia LLM（Gemma 4）
ailiaLLMSetPrompt → ailiaLLMGenerate
↓
戻り値のパース
<|tool_call> があればツール呼び出し、なければ最終回答
↓
ツールの実行
アプリケーション側で関数を実行
↓
結果を追記して再生成
<|tool_response> を会話に追加し、再度 ailiaLLMGenerate

制御トークン

Gemma 4 の Tool Use では次の制御トークンを使用します。開きトークンは <|name>、閉じトークンは <name|> の形です。

トークン用途形式
<|tool> … <tool|>ツール宣言（システムプロンプト）<|tool>declaration:名前{...}<tool|>
<|tool_call> … <tool_call|>ツール呼び出し（モデルの出力）<|tool_call>call:名前{引数}<tool_call|>
<|tool_response> … <tool_response|>ツール実行結果（アプリケーションが返す）<|tool_response>response:名前{結果}<tool_response|>
<|"|>文字列値のクォートkey:<|"|>value<|"|>
<|channel> … <channel|>Thinking（推論過程）出力の先頭に付く。回答には含めない

引数や結果は key:value をカンマで区切った形式です。文字列は <|"|> で囲み、数値と真偽値は cursor:0、literal:true のようにクォートなしで記述します。JSON とは異なり、キーはクォートしません。

システムプロンプトでのツール定義

Gemma 4 のチャットテンプレートは、ツール宣言をシステムターンの中に <|tool>declaration:...<tool|> として展開します。ailia LLM ではこの宣言文字列をシステムプロンプトの末尾に直接記述します。宣言の形式は次のとおりです（JSON Schema の内容を Gemma 4 の記法で記述します。type は大文字で STRING、INTEGER、BOOLEAN、OBJECT などを指定します）。

<|tool>declaration:get_current_temperature{description:<|"|>Gets the current temperature for a given location.<|"|>,parameters:{properties:{location:{description:<|"|>The city name, e.g. San Francisco<|"|>,type:<|"|>STRING<|"|>}},required:[<|"|>location<|"|>],type:<|"|>OBJECT<|"|>}}<tool|>

ailia Insight では、宣言だけでなく、自然文でのツール説明と呼び出し形式の指示をあわせてシステムプロンプトに含めています。宣言だけでは引数の型やクォートの規則が守られないことがあるため、次の 4 つの要素を空行で連結しています。

  1. 基本のシステムプロンプト（アシスタントの役割）
  2. ツールの一覧と使用ルール（1 応答につき 1 ツール呼び出し、すべて完了してから最終回答、など）と、各ツールの説明・パラメータ・呼び出し例
  3. 呼び出し形式の指示（下記）
  4. <|tool> 宣言
You are a helpful AI assistant with access to tools.

Rules:
1. Use exactly ONE tool call per response. Never call multiple tools at once.
2. After each tool response, decide the next step and either call another tool or provide the final answer.
3. Do NOT give your final answer until every part of the user's request is fulfilled.
4. When all steps are done, give your final answer as plain text.

### Available tools

- read_file_chunk: Read a chunk of text from a local file. Use cursor "0" for the first chunk, then pass the returned next_cursor to continue until eof is true.
  Parameters: {path:<|"|>...<|"|>,cursor:<|"|>...<|"|>,max_chars:<|"|>...<|"|>}
path: Local file path to read. (string, required).
cursor: Opaque cursor. Use 0 first, then reuse returned next_cursor. (integer, required). minimum 0.
max_chars: Maximum text characters to return. Use 12000 by default. (integer, optional). minimum 1.
  Examples:
  - Read the first chunk of a local text file.
    <|tool_call>call:read_file_chunk{path:<|"|>/home/user/file.txt<|"|>,cursor:0,max_chars:12000}<tool_call|>

Tool call format for this provider:
To call a tool, output exactly:
<|tool_call>call:TOOL_NAME{PARAM:<|"|>VALUE<|"|>}<tool_call|>

Every string value in tool calls must be wrapped with <|"|> on both sides. Integer and boolean values may be written without quotes, such as cursor:0 and literal:true. Multi-line string values are allowed inside <|"|>...<|"|>. To give your final answer, respond with plain text without tool_call tags.

<|tool>declaration:read_file_chunk{description:<|"|>Read a chunk of text from a local file. ...<|"|>,parameters:{path:<|"|>...<|"|>,cursor:<|"|>...<|"|>,max_chars:<|"|>...<|"|>}
path: Local file path to read. (string, required).
cursor: Opaque cursor. Use 0 first, then reuse returned next_cursor. (integer, required). minimum 0.
max_chars: Maximum text characters to return. Use 12000 by default. (integer, optional). minimum 1.}<tool|>
補足: ailia Insight では、ツール定義の source of truth を JSON Schema にし、Gemma 4 向けにはスキーマからパラメータの説明文（型・必須・最小値などを文章化したもの）を自動生成しています。型情報の弱い記法のため、整数や真偽値の制約は説明文に落とし込んでいます。

システムプロンプトは通常の system ロールのメッセージとして渡します。ailia LLM はプロンプトのトークナイズ時に特殊トークンを解釈するため、<|tool> などは文字列として含めるだけで正しく制御トークンになります。

import ailia_llm

model = ailia_llm.AiliaLLM()
model.open("gemma-4-E2B-it-Q4_K_M.gguf")

messages = [
    {"role": "system", "content": system_prompt},   # ツール宣言を含むシステムプロンプト
    {"role": "user", "content": "/home/user/file.txt の先頭を読んで要約してください。"},
]
response = "".join(model.generate(messages))

LLM からの戻り値

モデルがツールを使うと判断した場合、出力に <|tool_call> ブロックが含まれます。

<|tool_call>call:read_file_chunk{path:<|"|>/home/user/file.txt<|"|>,cursor:0,max_chars:12000}<tool_call|>

Thinking を有効にしている場合（ailiaLLMSetThinking）は、先頭に推論過程が付きます。

<|channel>The user wants a summary of a file, so I should read it first.<channel|><|tool_call>call:read_file_chunk{path:<|"|>/home/user/file.txt<|"|>,cursor:0,max_chars:12000}<tool_call|>

ツール呼び出しが不要な場合は、制御トークンを含まない平文が返ります。これを最終回答として扱います。

戻り値の判定は次のように行います。

戻り値の内容解釈次のアクション
<|tool_call>...<tool_call|> を含むツール呼び出し引数をパースしてツールを実行し、結果を返して再生成
制御トークンなしの平文最終回答ユーザーに表示して終了
Thinking のみで本文なし思考のみ回答を促すメッセージを追加して再生成
空、または形式が不正パースエラー期待する形式をエラーとして返して再生成

戻り値のパース

パースは 3 段階で行います。

  1. Thinking の分離: <|channel> から <channel|> までを取り除きます。Thinking を無効にしていても閉じトークン <channel|> だけが出力されることがあるため、その場合は <channel|> より前を Thinking として扱います。ただし前方に <|tool_call> がある場合は削らずそのまま残します。
  2. ツール呼び出しの抽出: 正規表現 <\|tool_call>call:(\w+)\{(.*)\}<tool_call\|>（DOTALL）で、ツール名と引数文字列を取り出します。
  3. 引数のデコード: 引数文字列を key:value のカンマ区切りとして解析します。値が <|"|> で始まる場合は次の <|"|> までを文字列として読み、それ以外は数値または真偽値として解釈します。

文字列値の中に \ や <|"|> のリテラルを含める場合は、\\ および <|\"|> のようにバックスラッシュでエスケープします。文字列は改行を含むことができます。文字列値の中にカンマが含まれることがあるため、単純に split(",") で分割せず、クォートを考慮して先頭から順に読み進める必要があります。

import re

QUOTE = '<|"|>'
TOOL_CALL = re.compile(r'<\|tool_call>call:(\w+)\{(.*)\}<tool_call\|>', re.DOTALL)

def extract_thinking(text):
    start = text.find('<|channel>')
    if start < 0:
        end = text.find('<channel|>')
        if end < 0 or '<|tool_call>' in text[:end]:
            return None, text
        return text[:end].strip(), text[end + len('<channel|>'):].strip()
    end = text.find('<channel|>', start)
    if end < 0:
        return text[start + len('<|channel>'):].strip(), text[:start].strip()
    thinking = text[start + len('<|channel>'):end].strip()
    return thinking, (text[:start] + text[end + len('<channel|>'):]).strip()

def parse_bare(value):
    low = value.lower()
    if low == 'true': return True
    if low == 'false': return False
    try: return int(value)
    except ValueError: pass
    try: return float(value)
    except ValueError: return value

def decode_args(src):
    result, i, n = {}, 0, len(src)
    while i < n:
        while i < n and src[i].isspace(): i += 1
        m = re.compile(r'\w+').match(src, i)
        if not m: return None
        key, i = m.group(0), m.end()
        while i < n and src[i].isspace(): i += 1
        if i >= n or src[i] != ':': return None
        i += 1
        while i < n and src[i].isspace(): i += 1
        if src.startswith(QUOTE, i):                      # 文字列値
            i += len(QUOTE); buf = []
            while i < n and not src.startswith(QUOTE, i):
                if src[i] == '\\' and i + 1 < n and src[i + 1] in ('\\', '"'):
                    buf.append(src[i + 1]); i += 2
                else:
                    buf.append(src[i]); i += 1
            if i >= n: return None                        # 閉じクォートなし
            i += len(QUOTE)
            result[key] = ''.join(buf)
        else:                                            # 数値 / 真偽値
            j = src.find(',', i)
            j = n if j < 0 else j
            result[key] = parse_bare(src[i:j].strip()); i = j
        while i < n and src[i].isspace(): i += 1
        if i < n:
            if src[i] != ',': return None
            i += 1
    return result or None

def parse_response(text):
    thinking, body = extract_thinking(text)
    m = TOOL_CALL.search(body)
    if m:
        return {"type": "tool_call", "name": m.group(1),
                "args": decode_args(m.group(2)), "thinking": thinking}
    if body.strip():
        return {"type": "final_answer", "content": body.strip()}
    if thinking:
        return {"type": "thought", "content": thinking}
    return {"type": "parse_error"}
補足: ストリーミング表示を行う場合は、閉じトークンまで揃った <|tool_call>...<tool_call|> と <|tool_response>...<tool_response|> のブロックを表示から除去し、末尾で閉じていない開きトークン以降も表示しないようにします。

ツール実行結果の返し方

ツールを実行したら、結果を <|tool_response> ブロックにして会話に追加し、再度生成します。結果は response:ツール名{...} の形式で、キーと値のペアで記述します。

<|tool_response>response:read_file_chunk{result:<|"|>（ファイルの内容）<|"|>}<tool_response|>

ailia LLM の API には tool ロールがないため、ailia Insight では会話履歴（ユーザー発話、モデルのツール呼び出し、ツール実行結果）をテキストとして順に連結し、1 つの user メッセージとしてシステムプロンプトと一緒に送信しています。モデルの過去のツール呼び出しは <|tool_call> 形式のまま履歴に書き戻します。

/home/user/file.txt の先頭を読んで要約してください。
<|tool_call>call:read_file_chunk{path:<|"|>/home/user/file.txt<|"|>,cursor:0,max_chars:12000}<tool_call|>
<|tool_response>response:read_file_chunk{result:<|"|>{"text":"...","next_cursor":12000,"eof":true}<|"|>}<tool_response|>
history = user_message
while True:
    messages = [{"role": "system", "content": system_prompt},
                {"role": "user", "content": history}]
    step = parse_response("".join(model.generate(messages)))
    if step["type"] == "tool_call":
        output = run_tool(step["name"], step["args"])      # アプリケーション側でツールを実行
        history += "\n" + build_tool_call(step["name"], step["args"])
        history += "\n" + build_tool_response(step["name"], output)
    elif step["type"] == "final_answer":
        print(step["content"]); break
    else:
        history += "\nError: Invalid input. Expected: <|tool_call>call:tool_name{param:<|"|>value<|"|>}<tool_call|>"

ツールの出力に <|"|> や \ が含まれる場合は、引数と同じ規則でエスケープしてから <|"|> で囲みます。

実装上の注意

  • 1 応答につき 1 ツール呼び出し: Gemma 4 は複数のツール呼び出しを並列に出力できますが、ailia Insight では処理を単純にするため 1 回に 1 つだけ呼ぶようシステムプロンプトで指示し、複数返された場合はエラーとして再試行しています。
  • Thinking の制御: ailiaLLMSetThinking で Thinking を有効にすると、ツールを使うかどうかの判断精度が上がりますが、生成時間が増えます。無効にしても推論過程を平文で出力することがあり、これがツール呼び出しなしの平文と区別できないため、システムプロンプトの先頭に「推論を書き出さず、ツール呼び出しか最終回答のみを返す」旨の指示を入れると安定します。
  • 入力の検証: モデルが返したツール名と引数は必ず検証してください。存在しないツール名、必須引数の欠落、パストラバーサル（..）などはエラーメッセージとしてモデルに返し、再試行させます。
  • 出力の長さ: ツールの実行結果はコンテキスト長を消費するため、一定の文字数で切り詰めてください。
  • コンテキスト長: システムプロンプトにツール宣言と履歴を含めるため、8K 以上のコンテキスト長を推奨します。
