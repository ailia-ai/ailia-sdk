ailia LLM Tool Use ガイド

ailia LLM の Tool Use API で Gemma 4 の Function Calling を使う方法を説明します。OpenAI 互換のツール定義、tool ロールによる実行結果の返却、生成結果の構造化をまとめます。

概要

ailia LLM 1.5.0 以降は Tool Use（Function Calling）API を搭載しています。OpenAI 互換の JSON でツールを定義すると、モデルのチャットテンプレート（llama.cpp）経由でツール宣言がプロンプトに展開され、出力はツール呼び出し構文の grammar で制約されます。生成されたテキストは ailiaLLMParseResponse で OpenAI 互換の tool_calls に変換でき、ツールの実行結果は tool ロールのメッセージとして履歴に追加します。

ツール宣言の記法、ツール呼び出しの構文、ツール実行結果の履歴への埋め込みはすべてチャットテンプレートが処理するため、Gemma 4 の制御トークンをアプリケーション側で組み立てたり解析したりする必要はありません。

注意: Tool Use API は ailia LLM 1.5.0 以降で利用できます。

対応モデル

  • Gemma 4 E2B / E4B / 26B-A4B / 31B（GGUF）

チャットテンプレートがツール呼び出しに対応しているモデルであれば、Gemma 4 以外でも同じ API で利用できます。ツール呼び出しの構文はモデルごとに異なりますが、宣言と解析はテンプレートに基づいてライブラリが行います。

全体フロー

Tool Use は、モデルがツール呼び出しを出力し、アプリケーションがツールを実行して結果を返し、モデルが最終回答を生成する、というループで実現します。

ailiaLLMSetTools（OpenAI 互換 JSON）

API

API説明
ailiaLLMSetTools(llm, tools_json)OpenAI 互換のツール定義（JSON 配列）を設定します。NULL または空文字列で解除します。次回の ailiaLLMSetPrompt からプロンプトに展開されます。
ailiaLLMSetPrompt の role: "tool"ツールの実行結果を返します。content には実行結果のテキスト（または JSON 文字列）をそのまま指定します。直前の assistant メッセージのツール呼び出しと順序で対応付けられます。
ailiaLLMSetPrompt の role: "assistant"ツール設定中は、モデルの生の出力（ailiaLLMGetDeltaText の連結）をそのまま指定します。内部で解析され、チャットテンプレートに合わせて再構成されます。
ailiaLLMParseResponseSize / ailiaLLMParseResponse(llm, text, ...)生の出力を OpenAI 互換の assistant メッセージ JSON（content / reasoning_content / tool_calls）に変換します。
AILIA_LLM_STATUS_PARSE_ERROR (-10)テキストがツール呼び出し構文と一致しない（生成途中のテキストなど）場合に返ります。

ツールの定義

ツールは OpenAI Chat Completions API の tools パラメータと同じ形式で定義します。parameters は JSON Schema です。宣言は Gemma 4 の <|tool>declaration:...<tool|> 形式にテンプレートが変換するため、型名の大文字化やクォート記法を意識する必要はありません。

[
  {
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "指定した都市の現在の天気を取得します。",
      "parameters": {
        "type": "object",
        "properties": {
          "city": {"type": "string", "description": "都市名"}
        },
        "required": ["city"]
      }
    }
  }
]

ツールを設定すると、モデルの出力はツール呼び出し構文の grammar で制約されます。クォートの欠落や不正な引数形式は生成段階で防がれるため、アプリケーション側での形式エラーの再試行は原則不要です。ツールを呼び出すかどうかの判断はモデルに委ねられ（tool_choice: auto 相当）、1 応答につき 1 つのツール呼び出しを出力します。

生成と戻り値の構造化

ailiaLLMGenerate / ailiaLLMGetDeltaText が返すテキストは、制御トークンを含むモデルの生の出力です。ツールを使うと判断した場合は次のような出力になります。

<|tool_call>call:get_weather{city:<|"|>東京<|"|>}<tool_call|>

生成完了までのテキストを ailiaLLMParseResponse に渡すと、OpenAI 互換の assistant メッセージが得られます。arguments は JSON 文字列、id はメッセージ内の出現順に call_0, call_1, ... です。

{
  "role": "assistant",
  "content": "",
  "tool_calls": [
    {"id": "call_0", "type": "function",
     "function": {"name": "get_weather", "arguments": "{\"city\":\"東京\"}"}}
  ]
}

Thinking を有効にしている場合（ailiaLLMSetThinking）、推論過程は content から分離され reasoning_content に入ります。ツール呼び出しが不要な場合は tool_calls が無く、content が最終回答です。

解析結果解釈次のアクション
tool_calls ありツール呼び出しarguments を JSON として読み、ツールを実行して結果を返して再生成
tool_calls なし、content あり最終回答ユーザーに表示して終了
reasoning_content のみ思考のみ回答を促すメッセージを追加して再生成
AILIA_LLM_STATUS_PARSE_ERROR生成が途中で終わった、または構文が一致しないコンテキスト長や生成の中断を確認して再生成

ツール実行結果の返し方

ツールを実行したら、次の 2 つのメッセージを履歴に追加して ailiaLLMSetPrompt を呼びます。

  1. role: "assistant"：モデルの生の出力をそのまま。ライブラリが解析し、チャットテンプレートに合わせてツール呼び出しを再構成します。
  2. role: "tool"：content にツールの実行結果（平文または JSON 文字列）をそのまま。直前の assistant のツール呼び出しと順序で対応付けられ、ツール名は自動的に補われます。

Gemma 4 には tool ロールが無く、ツール呼び出しと実行結果は同じ model ターンの中に <|tool_call> と <|tool_response> として並べる形式ですが、この変換はチャットテンプレートが行います。ツール未設定の状態で tool ロールを渡すと AILIA_LLM_STATUS_INVALID_STATE になります。

サンプルコード

Python

import json
import ailia_llm

model = ailia_llm.AiliaLLM()
model.open("gemma-4-E2B-it-Q4_K_M.gguf", n_ctx=4096)

# 1. ツール定義（OpenAI 互換）
model.set_tools([{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "指定した都市の現在の天気を取得します。",
        "parameters": {"type": "object",
                       "properties": {"city": {"type": "string"}},
                       "required": ["city"]},
    },
}])

def get_weather(city):
    return {"city": city, "weather": "晴れ", "temperature_c": 25}

messages = [{"role": "user", "content": "東京の今の天気を教えてください。"}]

while True:
    # 2. 生成（生の出力を蓄積し、そのまま assistant として履歴に追加）
    raw = "".join(model.generate(messages))
    messages.append({"role": "assistant", "content": raw})

    # 3. 戻り値の構造化
    response = model.parse_response(raw)
    if not response.get("tool_calls"):
        print(response["content"])          # 最終回答
        break

    # 4. ツールを実行して結果を tool として履歴に追加
    for call in response["tool_calls"]:
        args = json.loads(call["function"]["arguments"])
        result = get_weather(**args) if call["function"]["name"] == "get_weather" else {"error": "unknown tool"}
        messages.append({"role": "tool", "content": result})   # dict は JSON 化される

model.set_tools(None)   # ツールを解除

実装上の注意

  • ParseResponse の前提: 解析器は ailiaLLMSetPrompt の呼び出し時に、そのときのツール定義と Thinking 設定から生成されます。ailiaLLMSetPrompt の前、または ailiaLLMSetTools / ailiaLLMSetThinking の後に ailiaLLMSetPrompt を呼んでいない状態では AILIA_LLM_STATUS_INVALID_STATE になります。
  • 生成完了のテキストを渡す: 生成途中のテキストや、コンテキスト長超過で途切れた出力は AILIA_LLM_STATUS_PARSE_ERROR になります。ストリーミング表示中の判定には使わず、生成完了後に 1 回呼び出してください。
  • 履歴には生の出力を入れる: assistant の履歴には ailiaLLMParseResponse の結果ではなく、生の出力をそのまま入れます。ライブラリが解析して再構成するため、過去ターンの Thinking の除去や、ツール呼び出しを挟むターンでの Thinking の保持（Gemma 4 の仕様）も自動で満たされます。
  • ストリーミング表示: ailiaLLMGetDeltaText のテキストには <|tool_call> や <|channel> の制御トークンが含まれます。表示する場合はこれらのブロックを除去してください。
  • 入力の検証: ツール名は定義したものに制約されますが、引数の値（パスなど）はアプリケーション側で必ず検証してください。エラーは実行結果として tool メッセージで返し、モデルに再試行させます。
  • コンテキスト長: ツール宣言と履歴、ツールの実行結果を含めるため、4K 以上（複数ラウンドのエージェント用途では 8K 以上）のコンテキスト長を推奨します。ツールの実行結果は一定の文字数で切り詰めてください。
  • ツールの解除: ツールが不要になったら ailiaLLMSetTools(llm, NULL) で解除します。解除後は tool ロールを含む履歴は渡せません。
