ailia LLM NPU（QNN）ガイド

ailia LLM の QNN バックエンドを使用して、Qualcomm SoC の NPU で LLM / VLM を高速に推論する方法を説明します。

概要

ailia LLM は Qualcomm SoC の NPU（Hexagon）を使用した高速推論に対応しています。NPU 向けには、llama.cpp とは異なるアイリア社独自の実装を搭載しており、Android 端末上で Prefill を 10 倍以上高速化できます。テキストの LLM だけでなく、画像を入力する VLM（Vision Language Model）も NPU で処理できます。

QNN（Qualcomm AI Engine Direct）は Qualcomm が提供するバックエンド API です。ailia LLMでは、llama.cppのモデル形式であるGGUFを、QNNで実行可能な形式に変換することで、NPUでの推論を実現しています。

対応プラットフォーム

  • Android（Snapdragon 8 Gen 1 以降 / Hexagon v69 以降）
注意: ailia LLM の QNN バックエンドは現在 Android のみ対応です。Windows on Arm には未対応です。
注意: QNN（QAIRT）の対応バージョンは ailia SDK と同じ 2.47.0.260601 です。QNN Model は QNN SDK のバージョンにも依存するため、異なるバージョンの QNN ランタイムと組み合わせないでください。

ワークフロー

GGUF を PC 上で QNN Model に変換し、変換済みの QNN Model を端末上の ailia LLM で実行します。端末側では GGUF は不要で、QNN Model のみを配置します。

GGUF
llama.cpp 互換のモデルファイル（Q4 量子化）
↓
ailia LLM Compiler（PC）
QNN API でグラフを構築し、SoC 別の Context Binary を生成
↓
QNN Model（.qnn）
SoC 固有・自己完結のモデルファイル
↓
ailia LLM（Device）
Context Binary を復元し、Hexagon NPU で Prefill / Decode を実行

QNN Model は Prefill 用の固定長グラフ（AR-N）と Decode 用のグラフ（AR-1）を同じ QNN Context に格納し、重みと FP16 の KV キャッシュを共有します。重みは変換時に 4bit（W4）に量子化され、活性値と KV キャッシュは FP16 で処理されます。

対応モデル

現在は Gemma 4 E2B（テキストおよび VLM）に対応しています。VLM はテキスト用の QNN Model に加えて、画像エンコーダ（mmproj）用の QNN Model を使用します。

QNN Model は Snapdragon の機種（SoC）ごとに別ファイルになります。変換済みのモデルファイルを提供していますので、対象端末の SoC に対応したファイルをご利用ください。

ファイル内容
<soc>.qnn（例: sm8475.qnn）テキストモデル（Prefill + Decode）
<soc>-mmproj.qnn（例: sm8475-mmproj.qnn）VLM 用の画像エンコーダ（mmproj）
注意: QNN Model は Hexagon のバージョンだけでなく、QNN SDK のバージョンと SoC のモデル ID にも依存します。異なる SoC 向けのファイルを流用しないでください。実行中の端末に対応する SoC 名は ailiaLLMGetQNNModelName API で取得できます（例: "sm8475"）。

使用方法

Android への組み込み

libailia_llm.so に加えて、libailia_llm_qnn.so をアプリケーションの jniLibs/arm64-v8a に同梱します。アプリ側がロードするのは libailia_llm.so のみで、QNN Model を開いたときにだけ libailia_llm_qnn.so がプラグインとして遅延ロードされます。

libcdsprpc.so の使用を AndroidManifest.xml に記載する必要があります。また、NPU 側のライブラリ（libQnnHtpV*Skel.so）をファイルシステム経由で参照するため、extractNativeLibs を有効にします。

<application android:extractNativeLibs="true" ...>
    <uses-native-library android:name="libcdsprpc.so" android:required="false"/>
</application>

build.gradle に下記を追加すると、QNN ランタイムが自動的に apk に同梱されます。

implementation 'com.qualcomm.qti:qnn-runtime:2.47.0'
注意: QNN Model はファイルパスで指定するため、apk の assets を直接開くことはできません。初回起動時にアプリのプライベートストレージへコピー、またはダウンロードしてから開いてください。

QNN Model の読み込み

QNN Model（.qnn）は GGUF と同じモデル読み込み API に渡します。コンテキスト長に 0 を指定すると、QNN Model に埋め込まれた固定のコンテキスト長が使用されます。VLM の場合は、テキストモデルを開いた後に mmproj の QNN Model をプロジェクタとして開きます。

#include "ailia_llm.h"
struct AILIALLM *llm = nullptr;
ailiaLLMCreate(&llm);
ailiaLLMOpenModelFileA(llm, "sm8475.qnn", /*ctx_size=*/0);
ailiaLLMOpenMultimodalProjectorFileA(llm, "sm8475-mmproj.qnn"); // VLM のみ
// 以降は GGUF と同じ prompt / generate API を使用します
ailiaLLMDestroy(llm);

Kotlin（JNI）でも同様に、GGUF のパスの代わりに QNN Model のパスを渡します。

val llm = AiliaLLM()
llm.openModelFile(qnnModelPath, 0)            // n_ctx=0 で QNN Model 内の固定長を使用
llm.openMultimodalProjectorFile(mmprojQnnPath) // VLM のみ

アーキテクチャ

ailia LLM は QNN Model を mmap で読み込み、QNN Context を復元して Hexagon NPU（HTP）上で実行します。Prefill は固定長の AR-N グラフで処理し、プロンプトが AR の倍数でない場合は最後のスライスをパディングします。Decode は同じ Context 内の AR-1 グラフで処理し、Prefill 後の KV キャッシュのコピーは発生しません。VLM では画像のパッチ化と位置埋め込みを CPU で行い、16 層の Vision Transformer からプーリング、プロジェクションまでを 1 つの QNN グラフで実行します。

ベンチマーク

Gemma 4 E2B を Snapdragon 8+ Gen 1（SM8475 / Hexagon v69、ASUS AI2202）、QAIRT 2.47.0.260601 で測定した結果です。CPU は同じ端末上の llama.cpp 互換の CPU 実装（GGUF）、NPU は同じモデルから生成した QNN Model を使用し、同一プロンプト・greedy サンプリングで比較しています。

項目CPUNPU（QNN）高速化率
VLM 画像エンコーダ（768x768、1 枚）99.19 秒2.67 秒37.2 倍
VLM マルチモーダルプロンプト設定98.5 秒2.59 秒38.0 倍
VLM 画像入力から最初のトークンまで（TTFT）105.7 秒10.2 秒10.3 倍
テキスト Prefill（1000 トークン入力）-121.3 tokens/s-
テキスト Decode（ウォーム）11.4 tokens/s7.9 tokens/s0.7 倍
  • VLM の TTFT は、画像のデコード・前処理・画像エンコーダ・テキスト Prefill を含む時間です。VLM の行は画像エンコーダを CPU / NPU で切り替えた比較で、テキスト側はいずれも NPU で実行しています。
  • Prefill は Prefill 用グラフに LM head を統合した構成で、1000 トークン入力時の プロンプトのトークン数 / 最初の生成呼び出し時間 です。
  • Decode は Hexagon v69 では CPU の方が高速です。Hexagon v73 以降の新しい SoC では別途測定が必要です。
注意: ベンチマークは性能のみを示すもので、精度を保証するものではありません。現在、4bit 量子化に由来する精度問題（長いプロンプトでの単語の反復、VLM の画像埋め込みの数値誤差）を確認しており、今後修正予定です。

制約

  • QNN Model は SoC ごとに変換が必要で、他の SoC 向けのファイルは使用できません。
  • コンテキスト長と Prefill の固定長（AR）は変換時に決定され、実行時に変更できません。
  • VLM では 1 枚の画像トークン列（256 トークン）を分割せずに処理する必要があるため、テキスト側は AR-256 以上で変換した QNN Model を使用します。
  • 現在の対応モデルは Gemma 4 E2B のみです。
