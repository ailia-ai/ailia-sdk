ailia LLM MTP ベンチマーク

ailia LLM 1.5.1 の MTP（Multi-Token Prediction）を使用した、Qualcomm SoC の NPU と CPU における Gemma 4 の測定結果です。

MTP の仕組みと使い方は ailia LLM MTP ガイド、MTP を使わない QNN の測定結果は ailia LLM NPU（QNN）ベンチマーク を参照してください。

  • 結果の概要
  • 入力から回答完了までの時間（概算）
  • Android（Snapdragon 8+ Gen 1 / SM8475、Snapdragon 7s Gen 3 / SM7635）
  • Windows（Snapdragon X Plus / SC8380XP）

結果の概要

  • NPU のテキスト生成の Decode は、MTP により E2B で 1.81 倍（SM8475）、1.55 倍（SM7635）、1.50 倍（SC8380XP）、SC8380XP の E4B で 1.70 倍（非 MTP モデル比）、SM7635 の E4B で 1.01 倍です。
  • CPU（4 スレッド）のテキスト生成の Decode は、MTP により 0.94 倍（SM8475 E2B）、1.35 倍（SM7635 E2B）、1.65 倍（SM7635 E4B）です。
  • 音声の書き起こしでは、NPU の Decode は MTP により 1.66〜2.91 倍です。
  • MTP あり同士の Decode は、SM8475 の E2B で NPU が CPU の 1.12 倍、SM7635 の E2B で 0.87 倍です。Prefill は NPU が CPU の 3.0〜10.4 倍（2,048 トークン入力）、画像・音声入力の TTFT は NPU が CPU の 1/1.9〜1/6.9 です。
  • Prefill と TTFT は MTP の有無でほぼ同じです。

入力から回答完了までの時間（概算）

画像・音声を入力してから回答の生成が終わるまでの時間を、後述の TTFT と Decode スループットから概算した値です（TTFT + (出力トークン数 − 1) / Decode スループット）。画像は 100 トークン、音声は 32 トークンの出力です。Prefill・エンコーダの処理時間と Decode の処理時間の両方を含みます。

SM7635 E2B / Int16画像30.3 秒26.7 秒24.8 秒17.9 秒

NPU（MTP あり）は、CPU の短い方の構成と比べて 1/1.5〜1/2.9 の時間です。E2B では MTP なしと比べて 1.3〜1.5 倍短くなります。SM7635 の E4B の画像入力は、MTP の有無でほぼ同じです。実際に通しで測定した値ではないため、目安として参照してください。

Android

測定条件

Gemma 4 を 2 機種で測定した結果です。Snapdragon 8+ Gen 1（SM8475 / Hexagon v69）は E2B の FP16 モデル、Snapdragon 7s Gen 3（SM7635 / Hexagon v73）は E2B / E4B の Int16 モデルを使用しています。NPU の本体・Assistant は v1.5.1 の MTP 対応モデル（W4）で、QAIRT 2.47、コンテキスト長 8192、AR-256（Prefill）/ AR-4（検証）/ AR-1 構成です。2026-10-12 に測定しました。

CPU は同じ端末上で llama.cpp 経路を使用し、本体は GGUF（E2B は Q4_K_M、E4B は QAT Q4_0）、Assistant は Q4_0 の GGUF です。本体・Assistant・画像 / 音声エンコーダとも、スレッド数 4 で実行しています。QNN ベンチマークは Android の CPU をスレッド数 8 として測定しているため、CPU の値は一致しません。

CPU・NPU とも、「MTP なし」は Assistant を開かずに実行した値、「MTP あり」は同じ本体に Assistant を開いた値（ドラフト長 3）です。各条件は off → on → on → off の順に 2 回ずつ測定し、所要時間の中央値を示します。各試行は新しいインスタンスで実行し、試行間に 20 秒の間隔を置いています。TPS は最初の出力トークンを除いた時間から計算しています。サンプリングは greedy（temperature 0、top-k 1、top-p 1、seed 1234）です。MTP の有無で生成されるトークン列は異なります。

CPU 使用率は、プロセスの CPU 時間を経過時間と 8 コアで割った値で、8 コアすべてを使い切った状態を 100% とします。温度・クロックは固定していません。

81 トークン入力・1,000 トークン生成時のスループットです。受理率は、Assistant が提案した候補のうち本体の検証で採用された割合です。

NPU の Decode は、MTP により SM8475 の E2B で 1.81 倍、SM7635 の E2B で 1.55 倍、E4B で 1.01 倍になりました。CPU（4 スレッド）でも MTP を使用でき、SM7635 の E2B で 1.35 倍、E4B で 1.65 倍、SM8475 の E2B で 0.94 倍でした。MTP あり同士の比較では、NPU は CPU の 1.12 倍（SM8475 E2B）、0.87 倍（SM7635 E2B）、0.46 倍（SM7635 E4B）です。Decode 中のプロセス CPU 使用率は、CPU 実行で 42〜49%、NPU で 1.6〜5.0% です（CPU 使用率）。

MTP ありのグラフは、本体 1 回の実行（ラウンド）の所要時間を、そのラウンドで確定したトークン数で均等に割り当てて描いています。候補が多く受理されたラウンドでは TPS が高く、すべて外れたラウンドでは低くなるため、値が上下に振れます。凡例の TPS は全体の合計時間から計算した値です。

Windows

測定条件

Snapdragon X Plus（SC8380XP / Hexagon v73、8 コア）の Windows 11 Pro 上で、E2B / E4B の FP16 モデルを測定しました。同じ端末・同じビルドで、次の 3 構成を比較しています。

  • 非 MTP：v1.5.0 の従来モデル（gemma4-<model>-sc8380xp.qnn）
  • MTP なし：v1.5.1 の MTP 対応本体を Assistant なしで実行（AR-256 / AR-1）
  • MTP あり：v1.5.1 の MTP 対応本体 + Assistant（AR-256 / AR-4）

各構成 1 回の測定で、各試行の前に 60 秒待機しています。AC 接続、バランス電源プラン、4 つの高性能コアをワーカーとして使用し、背景アプリが動作している状態での測定です。CPU は同じ端末上で Q4_0 GGUF を標準の llama.cpp 経路（OpenMP 無効、4 つの高性能コアをワーカーとして使用、MTP なし）で実行した過去の測定値で、QNN ベンチマークと同じ測定です。GPU は Adreno X1-45 で、同じ Q4_0 GGUF を llama.cpp の OpenCL バックエンド（MTP なし）で実行した値です。GPU 実行時の性能を改善したランタイムで 2026-10-11 に測定しており、QNN ベンチマークの GPU の値より高速です。QCS6490 向けの MTP モデルはオフラインでのビルド確認のみで、実機での性能評価は未実施です。
