NXP i.MX 95 セットアップガイド

NXP FRDM i.MX 95 で ailia SDK をセットアップし、CPU・GPU (Vulkan)・NPU (Neutron) で推論を実行する手順を説明します。

概要

NXP i.MX 95 は、Arm Cortex-A55 CPU、Arm Mali-G310 GPU、NXP eIQ Neutron NPU を搭載した産業・車載向けのアプリケーションプロセッサです。本ページでは、開発ボード FRDM i.MX 95 上の Yocto Linux で ailia SDK を使用するためのセットアップ手順、実行方法、ベンチマーク結果を説明します。

ailia SDK が i.MX 95 で利用できる実行環境は次のとおりです。

実行環境ハードウェアailia SDK 公開版 (pip)ailia SDK NXP NPU 対応版 (1.8 ベータ)
CPUArm Cortex-A55対応対応
VulkanDNN (FP32 / FP16)Arm Mali-G310対応対応
Neutron-i.MX95-NPUNXP eIQ Neutron NPU非対応対応

NXP NPU 対応版は、ailia SDK 1.8 のベータ版という扱いで提供しています。

ボードのセットアップ

電源と USB シリアルの接続、Linux イメージの microSD への書き込み、起動とログインの手順は FRDM i.MX 95 ボードセットアップ を参照してください。

ailia SDK のインストール

Ethernet を接続した状態で、pip から ailia SDK をインストールします。AArch64 向けの wheel (manylinux2014_aarch64) が自動的に選択されます。

pip3 install ailia

インストール後、利用可能な実行環境を確認します。

python3 -c "import ailia; [print(i, ailia.get_environment(i)) for i in range(ailia.get_environment_count())]"
0 CPU
1 VulkanDNN-Mali-G310 (FP32)
2 VulkanDNN-Mali-G310 (FP16)
注意: pip 版の libailia.so が実際に参照するのは GLIBC 2.27 / GLIBCXX 3.4.22 までです。i.MX 95 の Yocto (glibc 2.43) ではそのまま動作します。

ライセンスの取得

pip 版は初回推論時に評価ライセンスを自動取得します。ボードに IPv6 のデフォルトルートがない環境では、ライセンスサーバーへの接続が OSError: [Errno 101] Network is unreachable で失敗することがあります。その場合は IPv4 を明示して取得してください。

mkdir -p ~/.shalo
curl -4 -fL https://axip-console.appspot.com/license/download/product/AILIA -o ~/.shalo/AILIA.lic

システム時刻が正しく設定されていることも確認してください。

NPU (Neutron) 対応版の導入

Neutron NPU を使用するには、ailia SDK の NXP NPU 対応版バイナリ (ailia SDK 1.8 ベータ版) を使用します。NXP NPU 対応版は ailia-sdk-nxp-demo リポジトリで配布しています。pip 版をインストールした後、パッケージ内の libailia.so を NXP NPU 対応版に差し替えます。

git clone https://github.com/ailia-ai/ailia-sdk-nxp-demo.git
cd ailia-sdk-nxp-demo
python3 scripts/copy_sdk.py --install-npu

差し替え前に、ailia を使用しているアプリケーションを終了してください。

注意: NXP NPU 対応版は NXP i.MX Distro 6.18-wrynose 向けにビルドしています (GLIBC_2.43 などに依存)。古い BSP では差し替えだけでは動作しません。

差し替え後に実行環境を列挙すると、/dev/neutron0 と libNeutronDriver.so が検出できる場合に Neutron-i.MX95-NPU が追加されます。NPU のない端末や Neutron ドライバのない環境では、CPU と Vulkan のみが列挙されます。

python3 -c "import ailia; [print(i, ailia.get_environment(i)) for i in range(ailia.get_environment_count())]"
0 CPU
1 VulkanDNN-Mali-G310 (FP32)
2 VulkanDNN-Mali-G310 (FP16)
3 Neutron-i.MX95-NPU

Neutron-i.MX95-NPU が表示されれば導入は完了です。表示されない場合はトラブルシューティングを確認してください。

ailia は NPU の初回利用時に、物理的に連続した 512 MiB の領域を CMA から確保します (メモリを参照)。動作確認環境の BSP イメージ (imx-image-full) では追加の設定なしで確保できます。確保に失敗する場合は grep Cma /proc/meminfo で CMA サイズを確認し、カーネル起動引数 cma= で拡大してください。

NPU で実行するには、行列積や畳み込みを標準 ONNX の整数演算 (MatMulNBits、MatMulInteger、ConvInteger) に変換したモデルを使用します (NPU 対応モデルの作り方を参照)。NPU に対応しないノードは自動的に CPU で実行されます。初回推論時に重みを NPU 向けに変換するため、初回のみ時間がかかります。

NPU 対応モデルの作り方

行列積や畳み込みを標準 ONNX の整数演算 (MatMulNBits、MatMulInteger、ConvInteger) に変換して NPU 用のモデルを作成する手順は、NPU 対応モデルの作り方 を参照してください。Transformer 向けの INT4 weight-only 量子化 (ViT-B/16)、MatMul の静的量子化 (SAM 2.1 Tiny、Grounding DINO、Depth Anything V2)、CNN 向けの畳み込みの静的量子化 (YOLOX-S) を例に説明しています。

実行方法

ailia-models のサンプルを使用して実行します。-e オプションで実行環境の ID を指定します。

git clone https://github.com/ailia-ai/ailia-models.git
cd ailia-models
pip3 install -r requirements.txt
cd image_classification/vit

# CPU
python3 vit.py -e 0
# Vulkan (Mali-G310 FP16)
python3 vit.py -e 2
# ベンチマークモード (11 回推論)
python3 vit.py -e 0 -b -bc 11

NPU で実行する場合は、INT4 (MatMulNBits) モデルを指定し、-e に Neutron-i.MX95-NPU の ID (上の列挙例では 3) を指定します。ViT では --quantize int4 オプションで INT4 モデルを使用できます。

python3 vit.py --quantize int4 -e <Neutron-i.MX95-NPU の ID> -b -bc 11
注意: シリアルコンソールから実行する場合は、-s output.png などで結果を画像ファイルとして保存してください。

ビジョンデモ (ailia-sdk-nxp-demo)

ailia-sdk-nxp-demo は、SAM 2.1 Tiny、Grounding DINO、Depth Anything V2、YOLOX-S 320 の COCO 校正済み NPU 用モデルを同梱した HDMI 画面のデモです。ailia と NXP ONNX Runtime の CPU / NPU、計 4 方式の速度を同じ画面で比較できます。HDMI ディスプレイとマウスを接続し、Weston と同じユーザーで実行します。

cd ailia-sdk-nxp-demo
python3 scripts/download_models.py   # SAM 2.1 の補助モデルを取得 (初回のみ)
sh launch.sh                          # SAM 2.1 Tiny (ailia NPU)
sh launch.sh --model grounding --caption "Horse. Clouds. Grasses. Sky. Hill."
sh launch.sh --model depth
sh launch.sh --model yolox

画面の Compare all 4 で 4 方式の推論時間を比較できます。USB カメラや動画ファイルを入力にすることもできます。詳細はリポジトリの README を参照してください。

CPU の値は最適化した FP32 モデルではなく、同じ ConvInteger モデルの値です。ailia の CPU 実行は、固定重みをキャッシュするタイル分割の NEON INT8 カーネルを使用します。ORT の Neutron EP では ConvInteger が CPU で実行されるため、ORT NPU は ORT CPU とほぼ同じ時間です。ailia NPU は、対応する演算の出力の再量子化を NPU 上で行います。CPU 実行とは丸め方が異なるため、出力は CPU 実行とビット単位では一致しません。

アーキテクチャ

ailia SDK は ONNX を入力し、グラフをパースし、レイヤーをインスタンス化します。NPU で実行できる標準 ONNX 整数演算 (MatMulNBits、MatMulInteger、ConvInteger) はモデルの読み込み時に NPU セグメントへ置き換えられ、それ以外のレイヤーは ailia_cpu で実行されます。static QDQ の DequantizeLinear → MatMul / Conv パターンは NPU 対応レイヤーとして直接認識しません。NPU セグメントは ONNX Runtime や TFLite の Execution Provider を経由せず、BSP に含まれる libNeutronDriver.so の低レベル API を直接呼び出します。libNeutronDriver.so は実行時に dlopen で読み込むため、NPU のない端末ではリンクエラーにならず、CPU と Vulkan のみで動作します。

使用する API

ailia は libNeutronDriver.so から次の関数を取得して使用します。

関数用途
allocateBuffer / releaseBufferNPU から参照できる CMA 領域の確保と解放
tiling_solver / weight_packer / compress_weight_tensor など重みを NPU 向けのタイル形式に変換 (pack)・圧縮
clean_cacheCPU のデータキャッシュを書き戻し、NPU と CPU の間でデータの一貫性を保つ
matmulNPU で行列積を実行 (完了まで待つ同期呼び出し)

メモリ

i.MX 95 の Neutron NPU は Arm CPU と同じ DRAM を共有します。ailia は allocateBuffer で物理的に連続した 512 MiB の CMA 領域を 1 つ確保し、プロセスのアドレス空間にマップされたポインタとして受け取ります。CPU はこの領域へ直接読み書きし、NPU は同じ物理メモリを参照するため、PCIe 接続の GPU のようなデバイスメモリへの転送はありません。

  • 先頭 320 MiB: pack 済みの重みなど、セッションの間保持するデータ
  • 末尾 192 MiB: 量子化した入力、INT32 の出力、行列積の設定 (ヘッダ) など、推論ごとに使う作業領域

行列積の設定ヘッダには、重み・入力・出力の位置を同じ領域内のオフセットとして記録します。ailia は CPU で書いたデータを clean_cache でメモリへ書き戻してから matmul を呼び、終了後に出力領域のキャッシュを整えてから CPU で読み出します。同じ領域を複数のモデルで共有するため、NPU の実行は排他制御で 1 つずつ行います。

ailia SDK を使用するメリット

推論ごとに結果が変わらない NPU 実行

NXP ONNX Runtime の Neutron 実行では、ViTおよびSAM 2.1 で同一入力に対する出力が推論ごとに変動することを確認しています。ailia は大きな行列を NPU が安定して処理できるサイズに分割することで出力変動 0 を実現しています。閾値判定や回帰テストなど、再現性が求められる製品用途に適しています。

Transformer と CNN の両方で高速

MatMulNBits と MatMulInteger の NPU 実行により、ViT では ORT NPU の 390.6 ms に対して ailia NPU は 317.3 ms (約 1.23 倍高速)、Grounding DINO では 7,549.9 ms に対して 4,068.0 ms (約 1.86 倍高速) でした。COCO 校正済み SAM 2.1 では Image Encoder が ailia CPU の 2,474.7 ms に対して ailia NPU で 877.8 ms、5 フレーム全体が 18.87 秒に対して 8.67 秒です。

CNN の畳み込みも、2D の ConvInteger として NPU で実行できます。ORT の Neutron EP は ConvInteger を CPU で実行するため、YOLOX-S では ORT NPU の 794.3 ms に対して ailia NPU は 114.9 ms (約 6.9 倍高速) でした。

両入力が動的な Attention の MatMul も NPU で実行

ONNX Runtime の Neutron EP が NPU で実行できるのは、右辺が定数重みの行列積だけです。Attention の QK・AV のように両入力が推論ごとに変わる MatMul は CPU に残ります。ailia は右辺を推論ごとに NPU 向けにパックすることで、両入力が動的な MatMulInteger も NPU で実行できます。SAM 2.1 の Memory Attention では、Attention の行列積を MatMulInteger として NPU で実行しています。Depth Anything V2 では、FP32 のまま残した Attention の MatMul 24 個を、ランタイムが推論時に INT8 に量子化して NPU で実行します。

CPU・GPU・NPU を同じ API で切り替え

実行環境 ID を変えるだけで、同じモデル・同じコードを CPU、Mali-G310 (Vulkan)、Neutron NPU で実行できます。Windows、macOS、Linux、Android、iOS と共通の C++ / Python / C# / Flutter API のため、PC で開発したアプリケーションをそのまま i.MX 95 へ移植できます。

400 以上のモデルと前後処理

ailia-models の 400 種類以上のモデルを i.MX 95 で試すことができます。また、ailia Speech (Whisper)、ailia Tokenizer、ailia LLM などのライブラリと組み合わせて、音声認識や生成 AI を組み込み機器に実装できます。

NPU のメモリ確保に失敗するailia は物理的に連続した 512 MiB の CMA 領域を確保します。grep Cma /proc/meminfo で CMA の合計と空きを確認し、不足する場合はカーネル起動引数 cma= で拡大してください。
初回の推論だけ遅い初回推論時に重みを NPU 向けに変換 (pack) するためで、正常な動作です。2 回目以降は短くなります。
NPU を指定しても速くならないNPU の対応条件 (zero point なし、K % 16 == 0 など) を満たさないノードは CPU で実行されます。NPU 対応モデルの作り方の確認スクリプトで、各ノードが NPU で実行されるか確認してください。
