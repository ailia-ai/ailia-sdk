NXP i.MX 95 セットアップガイド

NXP FRDM i.MX 95 で ailia SDK をセットアップし、CPU・GPU (Vulkan)・NPU (Neutron) で推論を実行する手順を説明します。

概要

NXP i.MX 95 は、Arm Cortex-A55 CPU、Arm Mali-G310 GPU、NXP eIQ Neutron NPU を搭載した産業・車載向けのアプリケーションプロセッサです。本ページでは、開発ボード FRDM i.MX 95 上の Yocto Linux で ailia SDK を使用するためのセットアップ手順、実行方法、ベンチマーク結果を説明します。

ailia SDK が i.MX 95 で利用できる実行環境は次のとおりです。

VulkanDNN (FP32 / FP16)Arm Mali-G310対応対応
Neutron-i.MX95-NPUNXP eIQ Neutron NPU非対応対応

NXP NPU 対応版は、ailia SDK 1.8 のベータ版という扱いで提供しています。

ボードのセットアップ

電源と USB シリアルの接続、Linux イメージの microSD への書き込み、起動とログインの手順は FRDM i.MX 95 ボードセットアップ を参照してください。

ailia SDK のインストール

Ethernet を接続した状態で、pip から ailia SDK をインストールします。AArch64 向けの wheel (manylinux2014_aarch64) が自動的に選択されます。

pip3 install ailia

インストール後、利用可能な実行環境を確認します。

python3 -c "import ailia; [print(i, ailia.get_environment(i)) for i in range(ailia.get_environment_count())]"
0 CPU
1 VulkanDNN-Mali-G310 (FP32)
2 VulkanDNN-Mali-G310 (FP16)
注意: pip 版の libailia.so が実際に参照するのは GLIBC 2.27 / GLIBCXX 3.4.22 までです。i.MX 95 の Yocto (glibc 2.43) ではそのまま動作します。

ライセンスの取得

pip 版は初回推論時に評価ライセンスを自動取得します。ボードに IPv6 のデフォルトルートがない環境では、ライセンスサーバーへの接続が OSError: [Errno 101] Network is unreachable で失敗することがあります。その場合は IPv4 を明示して取得してください。

mkdir -p ~/.shalo
curl -4 -fL https://axip-console.appspot.com/license/download/product/AILIA -o ~/.shalo/AILIA.lic

システム時刻が正しく設定されていることも確認してください。

NPU (Neutron) 対応版の導入

Neutron NPU を使用するには、ailia SDK の NXP NPU 対応版バイナリ (ailia SDK 1.8 ベータ版) を使用します。NXP NPU 対応版は ailia-sdk-nxp-demo リポジトリで配布しています。pip 版をインストールした後、パッケージ内の libailia.so を NXP NPU 対応版に差し替えます。

git clone https://github.com/ailia-ai/ailia-sdk-nxp-demo.git
cd ailia-sdk-nxp-demo
python3 scripts/copy_sdk.py --install-npu

差し替え前に、ailia を使用しているアプリケーションを終了してください。

注意: NXP NPU 対応版は NXP i.MX Distro 6.18-wrynose 向けにビルドしています (GLIBC_2.43 などに依存)。古い BSP では差し替えだけでは動作しません。

差し替え後に実行環境を列挙すると、/dev/neutron0 と libNeutronDriver.so が検出できる場合に Neutron-i.MX95-NPU が追加されます。NPU のない端末や Neutron ドライバのない環境では、CPU と Vulkan のみが列挙されます。

python3 -c "import ailia; [print(i, ailia.get_environment(i)) for i in range(ailia.get_environment_count())]"

NPU で実行するには、定数重みの MatMul を MatMulNBits (INT4) に変換したモデルを使用します (NPU 対応モデルの作り方を参照)。NPU に対応しないノードは自動的に CPU で実行されます。初回推論時に重みを NPU 向けに変換するため、初回のみ時間がかかります。

アーキテクチャ

ailia SDK は ONNX を入力し、グラフをパースし、レイヤーをインスタンス化します。NPU で実行できるレイヤー (MatMulNBits、MatMulInteger、ConvInteger、static QDQ の行列積など) はモデルの読み込み時に NPU セグメントへ置き換えられ、それ以外のレイヤーは ailia_cpu で実行されます。NPU セグメントは ONNX Runtime や TFLite の Execution Provider を経由せず、BSP に含まれる libNeutronDriver.so の低レベル API を直接呼び出します。libNeutronDriver.so は実行時に dlopen で読み込むため、NPU のない端末ではリンクエラーにならず、CPU と Vulkan のみで動作します。

使用する API

ailia は libNeutronDriver.so から次の関数を取得して使用します。

関数用途
allocateBuffer / releaseBufferNPU から参照できる CMA 領域の確保と解放
tiling_solver / weight_packer / compress_weight_tensor など重みを NPU 向けのタイル形式に変換 (pack)・圧縮
clean_cacheCPU のデータキャッシュを書き戻し、NPU と CPU の間でデータの一貫性を保つ
matmulNPU で行列積を実行 (完了まで待つ同期呼び出し)

メモリ

i.MX 95 の Neutron NPU は Arm CPU と同じ DRAM を共有します。ailia は allocateBuffer で物理的に連続した 512 MiB の CMA 領域を 1 つ確保し、プロセスのアドレス空間にマップされたポインタとして受け取ります。CPU はこの領域へ直接読み書きし、NPU は同じ物理メモリを参照するため、PCIe 接続の GPU のようなデバイスメモリへの転送はありません。

  • 先頭 320 MiB: pack 済みの重みなど、セッションの間保持するデータ
  • 末尾 192 MiB: 量子化した入力、INT32 の出力、行列積の設定 (ヘッダ) など、推論ごとに使う作業領域

行列積の設定ヘッダには、重み・入力・出力の位置を同じ領域内のオフセットとして記録します。ailia は CPU で書いたデータを clean_cache でメモリへ書き戻してから matmul を呼び、終了後に出力領域のキャッシュを整えてから CPU で読み出します。同じ領域を複数のモデルで共有するため、NPU の実行は排他制御で 1 つずつ行います。

NPU 対応モデルの作り方

基本構成: FP32 + NPU (INT8 MMA)

NPU を使う場合も、モデル全体を INT8 に量子化する必要はありません。基本構成は、モデルは FP32 のまま、定数の重みを持つ MatMul (全結合層) だけを MatMulNBits (INT4 重み) に変換する形です。変換した MatMulNBits は NPU で INT8 の積和演算 (MMA) として実行され、それ以外のレイヤーは FP32 のまま CPU で実行されます。

演算モデル内の形式実行先と精度
定数重みの MatMul (Attention の Q/K/V・出力投影、MLP など)MatMulNBits (INT4 重み)NPU: 入力を INT8 に動的量子化し、INT8 × INT8 を INT32 で累積して FP32 に戻す
LayerNorm、Softmax、GELU、残差の AddFP32CPU: FP32
Attention の QK / AV など入力同士の MatMulFP32CPU: FP32

この構成には次の利点があります。

  • キャリブレーションが不要: 重みだけを量子化 (weight-only) し、入力は推論ごとに動的に量子化するため、キャリブレーション用のデータセットを用意する必要がありません。
  • 精度を保ちやすい: 量子化に弱い LayerNorm や Softmax は FP32 のまま計算します。ViT-B/16 では FP32 と INT4 で top-5 の順位が一致しました。
  • モデルが小さい: 重みが 4 bit になるため、ViT-B/16 は 330.3 MiB から 49.3 MiB になります。

MatMulNBits は 4 bit の重みにのみ対応しています。重みを 8 bit で量子化する場合は、MatMulNBits ではなく DynamicQuantizeLinear + MatMulInteger の構成にしてください。ONNX Runtime の quantize_dynamic で MatMul を量子化すると、この構成のモデルが得られます。この場合も入力は推論ごとに動的に量子化されるため、キャリブレーションは不要です。

from onnxruntime.quantization import quantize_dynamic, QuantType

quantize_dynamic(
    "ViT-B_16-224.onnx",
    "ViT-B_16-224-int8.onnx",
    op_types_to_quantize=["MatMul"],
    weight_type=QuantType.QInt8,
)

NPU で実行できるレイヤー

ailia SDK と NXP ONNX Runtime (Neutron Execution Provider) が NPU で実行するレイヤーは次のとおりです。いずれも条件を満たさないノードは CPU で実行されます。

ランタイムレイヤー条件
ailia SDKMatMulNBits4 bit、zero point なし、定数重み、K % 16 == 0、N % 128 == 0
DynamicQuantizeLinear + MatMulIntegerINT8 / UINT8。定数重みに加え、両入力が動的な行列積にも対応
ConvInteger1D (NCL)、group 1、UINT8 入力、定数重み
static QDQ の MatMul・ConvQuantizeLinear / DequantizeLinear で挟んだ INT8 演算。Conv は 2D、group 1、K % 64 == 0、N % 128 == 0 で、既定では演算量の大きい形状のみ
NXP ONNX RuntimeMatMulNBits4 bit、zero point なし、定数重み、K % 16 == 0、N % 128 == 0
MatMulInteger、MatMulIntegerToFloat、QLinearMatMul、QGemm定数重み、N % 16 == 0

NXP ONNX Runtime では、static QDQ モデル (ViT、ResNet-50) を Neutron EP で実行しても、行列積と畳み込み (QLinearMatMul、QGemm、QLinearConv) はすべて CPU で実行され、NPU による高速化は得られませんでした。

MatMulNBits への変換

変換は PC で ONNX Runtime の MatMulNBitsQuantizer を使って行います。ailia-models の ViT のエクスポートサンプル (image_classification/vit/export/export_int4.py) が参考になります。このサンプルは ailia-models PR #1966 で追加予定です。MatMulNBits の仕組みについては MatMulNBits : LLM や VLM を ONNX で動かすための 4bit 量子化 を参照してください。

pip3 install onnxruntime onnx numpy
cd ailia-models/image_classification/vit/export
python3 export_int4.py

FP32 モデルをダウンロードし、MatMulNBits へ変換して、ViT-B_16-224-int4.onnx と ailia 用の .prototxt を出力します。変換の中心部分は次のとおりです。

import onnx
from onnxruntime.quantization.matmul_nbits_quantizer import MatMulNBitsQuantizer
from onnxruntime.quantization.quant_utils import QuantFormat

model = onnx.load("ViT-B_16-224.onnx")
quantizer = MatMulNBitsQuantizer(
    model=model,
    block_size=128,
    is_symmetric=True,
    accuracy_level=4,
    quant_format=QuantFormat.QOperator,
    op_types_to_quantize=("MatMul",),
)
quantizer.process()
onnx.save(quantizer.model.model, "ViT-B_16-224-int4.onnx")
パラメータ値意味
op_types_to_quantize("MatMul",)MatMul だけを変換します。重みが定数でない MatMul (Attention の QK / AV) は自動的に FP32 のまま残ります。
block_size128scale を共有する重みのブロックサイズ
is_symmetricTruezero point なしの対称量子化。NPU は zero point 付きに対応していません。
accuracy_level4入力を INT8 に量子化し、INT32 で累積する
quant_formatQOperatorMatMulNBits ノードとして出力する

ViT-B/16 では、定数重みの MatMul 72 個が MatMulNBits に変換され、Attention の MatMul 24 個と分類ヘッドの Gemm 1 個は FP32 のまま残ります。

NPU で実行されるのは、MatMulNBits のうち K が 16 の倍数、N が 128 の倍数で、zero point を持たないものです。条件を満たさないノードは自動的に CPU で実行されるため、エラーにはなりません。変換後のモデルは次のように確認できます。

import collections, onnx

model = onnx.load("ViT-B_16-224-int4.onnx")
print(collections.Counter(n.op_type for n in model.graph.node))
for node in model.graph.node:
    if node.op_type == "MatMulNBits":
        a = {x.name: onnx.helper.get_attribute_value(x) for x in node.attribute}
        ok = a["bits"] == 4 and a["K"] % 16 == 0 and a["N"] % 128 == 0 and len(node.input) <= 3
        print(node.name, a["K"], a["N"], "OK" if ok else "CPU")

ailia で読み込むための .prototxt は export-to-onnx の onnx2prototxt.py で生成します (エクスポートサンプルは自動で生成します)。

python3 onnx2prototxt.py ViT-B_16-224-int4.onnx

実行方法

ailia-models のサンプルを使用して実行します。-e オプションで実行環境の ID を指定します。

git clone https://github.com/ailia-ai/ailia-models.git
cd ailia-models
pip3 install -r requirements.txt
cd image_classification/vit

# CPU
python3 vit.py -e 0
# Vulkan (Mali-G310 FP16)
python3 vit.py -e 2
# ベンチマークモード (11 回推論)
python3 vit.py -e 0 -b -bc 11

NPU で実行する場合は、INT4 (MatMulNBits) モデルを指定し、-e に Neutron-i.MX95-NPU の ID を指定します。ViT の INT4 オプションは ailia-models PR #1966 で追加予定です。

python3 vit.py --quantize int4 -e <Neutron-i.MX95-NPU の ID> -b -bc 11
注意: シリアルコンソールから実行する場合は、-s output.png などで結果を画像ファイルとして保存してください。

ailia を使うメリット

推論ごとに結果が変わらない NPU 実行

NXP ONNX Runtime の Neutron 実行では、ViTおよびSAM 2.1 で同一入力に対する出力が推論ごとに変動することを確認しています。ailia は大きな行列を NPU が安定して処理できるサイズに分割することで出力変動 0 を実現しています。閾値判定や回帰テストなど、再現性が求められる製品用途に適しています。

Transformer モデルで高速

MatMulNBits の NPU 実行に加えて、ARM NEON による INT4 CPU カーネル、Whisper の KV キャッシュなどにより、ViT で ONNX Runtime 比 1.08 倍、Whisper large-v3-turbo で 1.85 倍、SAM 2.1 の Image Encoder で 2.2 倍の速度を実測しました。セッション生成も高速で、SAM 2.1 では ONNX Runtime NPU の 4.2 秒に対し 2.0 秒です。

両入力が動的な Attention の MatMul も NPU で実行

ONNX Runtime の Neutron EP が NPU で実行できるのは、右辺が定数重みの行列積だけです。Attention の QK・AV のように両入力が推論ごとに変わる MatMul は CPU に残ります。ailia は右辺を推論ごとに NPU 向けにパックすることで、MatMulInteger や static QDQ 形式であれば、両入力が動的な MatMul も NPU で実行できます。Whisper のエンコーダや SAM 2.1 の Memory Attention では、Attention の行列積も NPU で実行しています。

ONNX Runtime や TFLite に依存しない

ailia は libNeutronDriver.so の低レベル API を直接呼び出し、対応ノードの抽出、重みの pack、CMA メモリ管理、CPU フォールバックを自身で管理します。Neutron ドライバは実行時に動的ロードするため、NPU のない i.MX や他の Linux 端末でも同じバイナリが CPU / Vulkan で動作します。

CPU・GPU・NPU を同じ API で切り替え

実行環境 ID を変えるだけで、同じモデル・同じコードを CPU、Mali-G310 (Vulkan)、Neutron NPU で実行できます。Windows、macOS、Linux、Android、iOS と共通の C++ / Python / C# / Flutter API のため、PC で開発したアプリケーションをそのまま i.MX 95 へ移植できます。

400 以上のモデルと前後処理

ailia-models の 400 種類以上のモデルを i.MX 95 で試すことができます。また、ailia Speech (Whisper)、ailia Tokenizer、ailia LLM などのライブラリと組み合わせて、音声認識や生成 AI を組み込み機器に実装できます。
