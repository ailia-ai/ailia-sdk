NXP i.MX 95 ベンチマーク

NXP FRDM i.MX 95 で、ailia SDK (NXP NPU 対応版) と NXP ONNX Runtime の CPU・NPU 実行を比較したベンチマークの詳細です。結果の概要とセットアップ手順は NXP i.MX 95 セットアップガイド を参照してください。

測定条件

FRDM i.MX 95 で、ailia SDK (NXP NPU 対応版) と NXP BSP 同梱の ONNX Runtime 1.24.3 (ORT) を比較しました。すべてのモデルを 2026-11-22 に ailia のランタイム c8e3d217e で測定しています。いずれも CPU 6 スレッド、プロファイル無効で、NPU の値は非対応レイヤーの CPU 実行を含みます。モデルは各方式で同じものを使用しています。

ORT は、NPU 用に確保する CMA を 512 MiB に固定して測定しています。動作確認環境のボードの CMA は 960 MiB で、ORT の既定の 2 GiB では確保に失敗し、CPU にフォールバックするためです。ailia はこの設定を使用しません。

ViT-B/16 (画像分類、224×224)

ailia-models で公開している INT4 モデル (ViT-B_16-224-int4.onnx) を使用しています。定数重みの MatMul を MatMulNBits INT4 に変換し、その他の演算を FP32 で実行するモデルです。入力画像はデモ同梱の images/vit/input.jpg、バッチ 1 です。モデル Open 時のダミー推論 1 回を除外し、続く 10 回の中央値を示します。前処理・後処理・描画は含みません。

項目ORT CPUORT NPUailia CPUailia NPU
推論時間 (中央値)670.2 ms385.9 ms780.7 ms328.8 ms
FPS1.492.591.283.04

ailia NPU は ORT NPU の約 1.17 倍の速度です。4 方式とも、10 回すべてで Labrador retriever (ImageNet のクラス 208) に分類しました。ORT NPU では、別途プロファイルを有効にした実行で、MatMulNBits 72 個がすべて Neutron で実行されることを確認しています。

2026-11-18 の測定では、同じ入力を繰り返し推論したときの出力の最大絶対差 (出力変動) も比較しました。ORT NPU のみ 0.2002 の変動があり、ORT CPU・ailia CPU・ailia NPU は 0 (毎回同じ結果) でした。

SAM 2.1 Tiny (セグメンテーション、512×512)

ailia-sdk-nxp-demo の COCO 校正済みモデル coco-val2017-v1 を使用し、ailia の CPU 実行には NEON 最適化した整数 MatMul を使用しています。全方式でモデル Open 時に同じダミー入力で 1 回推論し、その後 Bedroom の 5 フレームを同じ 2 点で 1 周ウォームアップしました。続く 3 回の中央値で、ウォームアップは測定に含みません。

モデル別は 1 回あたりの平均時間の中央値です。静止画 1 枚は Image Encoder と Mask Decoder の合計で、前後処理を含みません。動画 1 フレーム平均は 5 フレーム全体の時間を 5 で割った値で、画像読み込み・前後処理を含み、モデル読み込み・描画・保存を除きます。4 方式とも同じモデルを使用します。NPU 方式では Image Encoder と Memory Attention を CPU / NPU 混在で実行し、その他は CPU 実行です。

※ ORT NPU はこの測定でも追跡マスクが正しくないため、速度参考値です。速度測定は精度の確認を兼ねていません。

以前の測定では、Bedroom での FP32 参照に対する平均マスク IoU は、ホスト ORT CPU で 96.07%、実機 ailia NPU で 95.71% でした。正解マスクに対する精度ではありません。

Grounding DINO Swin-T (オープン語彙物体検出、400×599)

COCO で校正したモデル grounding-coco-val2017-ql-v3 を使用し、入力画像はデモ同梱の images/grounding_dino/demo.jpg、プロンプトは Horse. Clouds. Grasses. Sky. Hill. です。モデル Open 時のダミー推論 1 回を除外し、続く 3 回の中央値を示します。モデル読み込みと前後処理は含みません。

項目ORT CPUORT NPUailia CPUailia NPU
推論時間 (中央値)7,531.2 ms6,979.8 ms6,104.4 ms3,840.2 ms
検出数15141515

固定重みの MatMul 347 個と、両入力が動的な MatMul 109 個を、いずれも校正済みの QuantizeLinear + MatMulInteger に変換したモデルです。ailia NPU では固定重みの MatMul を NPU で実行し、両入力が動的な MatMul は行列が小さいため CPU の NEON 整数演算で実行します。以前の動的量子化のモデルと比べて馬の検出 7 個は維持され、検出枠の IoU は平均 0.987 (最小 0.978) でした。検出精度 (mAP) の評価ではなく、デモ画像での出力の比較です。ORT NPU は推論ごとに出力が変動することがあります。

Depth Anything V2 Metric Depth Small (屋内深度推定、518×518)

COCO で校正したモデル depth-coco-val2017-conv-v4 を使用し、入力は Bedroom の 1 フレーム目 (00000.jpg) です。モデル Open 時のダミー推論 1 回を除外し、続く 3 回の中央値を示します。モデル読み込み・前処理・描画は含みません。

項目ORT CPUORT NPUailia CPUailia NPU
推論時間 (中央値)2,796.2 ms2,575.9 ms3,125.7 ms2,045.1 ms

固定重みの MatMul 48 個、Attention の MatMul 24 個、畳み込み 28 個を、校正済みの QuantizeLinear と MatMulInteger / ConvInteger に変換したモデルです。ailia NPU はこれらを NPU で実行します。出力側の高解像度で細い畳み込み 3 個は、NPU のほうが遅かったため FP32 のまま残しています。Softmax と ConvTranspose も FP32 です。ORT の Neutron EP が NPU で実行するのは固定重みの MatMul のみです。

以前の Bedroom 5 フレームでの比較では、ailia CPU と ailia NPU の出力の差は平均 1.14 cm (最大 23.84 cm)、ORT CPU との差は平均 4.55 cm (最大 50.15 cm)、畳み込みを量子化する前の NPU 用モデルとの差は平均 4.90 cm (最大 59.79 cm) でした。いずれも出力どうしの比較で、正解深度に対する精度ではありません。

YOLOX-S (物体検出、320×320)

COCO 校正済みの INT8 モデル (ConvInteger 83 個) を使用し、バッチ 1、入力画像はデモ同梱の images/yolox/input.jpg です。モデル Open 時のダミー推論 1 回を除外し、続く 10 回の中央値を示します。前処理・NMS・描画は含みません。

項目ORT CPUORT NPUailia CPUailia NPU
推論時間 (中央値)793.9 ms795.7 ms436.9 ms114.8 ms
FPS1.261.262.298.71

CPU の値は最適化した FP32 モデルではなく、同じ ConvInteger モデルの値です。ailia の CPU 実行は、固定重みをキャッシュするタイル分割の NEON INT8 カーネルを使用します。ORT の Neutron EP では ConvInteger が CPU で実行されるため、ORT NPU は ORT CPU とほぼ同じ時間です。ailia NPU は、対応する演算の出力の再量子化を NPU 上で行います。CPU 実行とは丸め方が異なるため、出力は CPU 実行とビット単位では一致しません。

COCO val2017 全 5,000 枚での AP は、FP32 (ホスト ORT CPU) の 30.42 に対し、INT8 (ailia NPU) で 29.00 (-1.42 ポイント) です。評価に使用した画像は校正データと同じため、独立したテストセットでの精度ではありません。
