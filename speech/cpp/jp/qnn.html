Linux ARM64版は、glibc 2.35以下・GLIBCXX_3.4.29以下を要求する構成でビルドしています。検証環境のシステムC++ランタイムで実行できます。

以下では、配布パッケージに含まれるLinux ARM64サンプルを使用します。 サンプルはビルド済みのため、実機へのコンパイラ導入やサンプルのビルドは不要です。 BSPにはCDSPファームウェア、FastRPCのlibcdsprpc.so、CDSPデバイスへのアクセス権が必要です。

1. 必要なファイルを取得する（ホストPC）

ailia Speech SDKの配布パッケージを展開します。以下のファイルも取得してください。

  • Whisper Large-v3-Turbo / QCS6490
  • Whisper Medium / QCS6490
  • Qualcomm QAIRT SDK 2.47.0.260601

モデルはTurboまたはMediumのどちらかを選択できます。以下ではTurboを使用します。 QAIRT SDKを展開し、SPEECH_PACKAGEとQNN_SDK_PATHを各パッケージの展開先に設定します。

export SPEECH_PACKAGE=/path/to/ailia_speech_package
export QNN_SDK_PATH=/path/to/qairt/2.47.0.260601
export DEPLOY="$PWD/qnn-yocto"
mkdir -p "$DEPLOY"

2. サンプルと依存ライブラリをコピーする（ホストPC）

パッケージの cpp/prebuilt/linux/arm64-v8a/ には、次のファイルが含まれています。 ailia SDK、ailia Audio、ailia Tokenizerのネイティブライブラリを別途取得する必要はありません。

ファイル 用途
ailia_speech_sample C++サンプル実行ファイル
libailia_speech.so 音声認識ライブラリ
libailia_speech_qnn.so QNNプラグイン
libailia.so ailia SDK
libailia_audio.so 音声前処理
libailia_tokenizer.so トークナイザー

これらを作業フォルダへまとめてコピーします。

cp -R "$SPEECH_PACKAGE/cpp/prebuilt/linux/arm64-v8a/." "$DEPLOY/"
cp "$SPEECH_PACKAGE/cpp/demo.wav" "$DEPLOY/"
curl -L --fail -o "$DEPLOY/whisper-large-v3-turbo-qcs6490-int16.qnn" \
https://storage.googleapis.com/ailia-models/whisper/qnn/v1.6.0/whisper-large-v3-turbo-qcs6490-int16.qnn

3. QNNライブラリをコピーする（ホストPC）

QAIRT SDKからYocto用の aarch64-oe-linux-gcc11.2 と、Hexagon v68のskelをコピーします。 Android用やWindows用のバイナリは使用しません。 FastRPCライブラリとCDSPファームウェアは実機BSPのものを使用します。

cp "$QNN_SDK_PATH/lib/aarch64-oe-linux-gcc11.2/libQnnHtp.so" "$DEPLOY/"
cp "$QNN_SDK_PATH/lib/aarch64-oe-linux-gcc11.2/libQnnSystem.so" "$DEPLOY/"
cp "$QNN_SDK_PATH/lib/aarch64-oe-linux-gcc11.2/libQnnHtpV68Stub.so" "$DEPLOY/"
cp "$QNN_SDK_PATH/lib/hexagon-v68/unsigned/libQnnHtpV68Skel.so" "$DEPLOY/"

4. 実機へ転送する（ホストPC）

接続先IPとユーザー名を実機に合わせて変更してください。評価ライセンスが必要な場合は、 実機の ~/.shalo/ailia.lic へ有効なライセンスを配置します（セットアップ）。

scp -r "$DEPLOY" root@169.254.239.42:/home/root/

5. C++サンプルを実行する（実機）

以降は実機上で実行します。サンプルは自身のフォルダからailiaのライブラリを読み込み、 QNNプラグインは同じフォルダのQNNライブラリとv68 skelを読み込むため、LD_LIBRARY_PATHの設定は不要です。 モデルのパスを第2引数へ渡します。cpuは音声前処理等の補助処理に使うailia環境の指定です。 QNNモデルの音声認識はHTP / NPUで実行されます。VAD・話者識別・ポストプロセスは無効です。

cd /home/root/qnn-yocto
chmod +x ./ailia_speech_sample
./ailia_speech_sample demo.wav whisper-large-v3-turbo-qcs6490-int16.qnn \
auto transcribe vad_disable diarization_disable none cpu

6. Pythonから実行する（実機）

Pythonパッケージをインストールする

Python 3とpip3を使用します。BSPにpip3がない場合は、次のコマンドで用意します。

curl -L --fail -o get-pip.py https://bootstrap.pypa.io/get-pip.py
python3 get-pip.py

SDKパッケージからインストールする場合は、SDKを実機上にも展開して次を実行します。 bootstrap.pyで同梱ライブラリをPythonパッケージへコピーした後、pip3 install . でインストールします。

cd /path/to/ailia_speech_package/python
python3 bootstrap.py
pip3 install .

公開版を使用する場合は、代わりに次を実行します。

pip3 install ailia_speech

インストール先にQNNライブラリをコピーする

pip3 showで表示されるLocationがsite-packagesのパスです。 その下の ailia_speech/linux/arm64-v8a/ にlibailia_speech_qnn.soがインストールされます。 QNNライブラリとv68 skelをこのファイルの横へコピーします。

pip3 show ailia_speech
SITE_PACKAGES=$(pip3 show ailia_speech | sed -n 's/^Location: //p')
SPEECH_NATIVE="$SITE_PACKAGES/ailia_speech/linux/arm64-v8a"
test -f "$SPEECH_NATIVE/libailia_speech_qnn.so"
cd /home/root/qnn-yocto
cp libQnnHtp.so libQnnSystem.so libQnnHtpV68Stub.so libQnnHtpV68Skel.so "$SPEECH_NATIVE/"

ライブラリを配置した後でPythonを起動します。GLIBCXX_3.4.29以上のシステムのC++ランタイムを使用するため、追加のLD_LIBRARY_PATH設定は不要です。

アプリケーションからローカルモデルを開く

open()は指定したローカルファイルを開きます。モデルを自動ダウンロードするinitialize_model()の代わりに使用します。 次のコードを実機の /home/root/qnn-yocto/transcribe_qnn.py に保存してください。 soundfileで音声をfloat32として読み込み、モデルの読み込みから認識結果の表示までを実行します。 サンプルで使用するsoundfileをインストールしてください。

pip3 install soundfile

読み込んだ音声はailia Speechが受け取る (channels, samples) の形に転置します。 get_qnn_model_name()で実機のモデル識別名を取得します。set_qnn_graph_switching(True)はopen()の前に呼び、HTPメモリ使用量を抑えます。推論時間が増える場合があります。 QNNはファイルを1つ指定します。TurboにはPythonのTurbo定数を既定値として使用します。

import argparse
import soundfile as sf
import ailia_speech
parser = argparse.ArgumentParser()
parser.add_argument("--model", required=True)
parser.add_argument("--input", required=True)
parser.add_argument("--model-type", type=int,
default=ailia_speech.AILIA_SPEECH_MODEL_TYPE_WHISPER_MULTILINGUAL_LARGE_V3_TURBO)
parser.add_argument("--language", default=None)
args = parser.parse_args()
waveform, sampling_rate = sf.read(args.input, dtype="float32", always_2d=True)
waveform = waveform.T
speech = ailia_speech.Whisper()
print("QNN model:", speech.get_qnn_model_name())
speech.set_qnn_graph_switching(True)
speech.open(
args.model,
model_type=args.model_type,
vad_path=None,
segmentation_path=None,
embedding_path=None,
)
for segment in speech.transcribe(waveform, sampling_rate, lang=args.language):
print(segment["text"], flush=True)

手順6でQNNライブラリを配置した後に実行します。言語は自動判定します。日本語へ固定する場合は –language ja を追加します。

cd /home/root/qnn-yocto
python3 transcribe_qnn.py \
--model ./whisper-large-v3-turbo-qcs6490-int16.qnn --input ./demo.wav

ONNXの場合はopen(encoder_path, decoder_path, model_type=...)で2つのファイルを指定します。

VADを使用する場合はvad_path="silero_vad_v6_2.onnx"のようにローカルのONNXファイルを指定します。 話者分離を使用する場合はsegmentation_path="segmentation.onnx"とembedding_path="speaker-embedding.onnx"の両方を指定します。 これらのONNXモデルはQNNの音声認識モデルと併用できます。各パスの既定値はNoneで、指定しなければ読み込みを省略します。 vad_typeの既定値はSilero、diarization_typeの既定値はPyannoteです。VADを指定するとinitialize_model()と同じ無音判定の設定が適用されます。 FP16やVADのバージョンは指定するファイルで選択します。ONNXの外部重みファイルはONNXが参照する場所に配置してください。 Noneは既に読み込んだモデルを解除する指定ではありません。

Mediumモデルを使用する場合

手順2のTurboモデルの代わりに、Mediumモデルをダウンロードして実機へ転送します。

curl -L --fail -o "$DEPLOY/whisper-medium-qcs6490-int16.qnn" \
https://storage.googleapis.com/ailia-models/whisper/qnn/v1.6.0/whisper-medium-qcs6490-int16.qnn
scp "$DEPLOY/whisper-medium-qcs6490-int16.qnn" root@169.254.239.42:/home/root/qnn-yocto/

実機の /home/root/qnn-yocto で実行するコマンドです。Pythonは手順6のライブラリ配置を行ってください。

./ailia_speech_sample demo.wav whisper-medium-qcs6490-int16.qnn \
auto transcribe vad_disable diarization_disable none cpu
python3 transcribe_qnn.py \
--model ./whisper-medium-qcs6490-int16.qnn --input ./demo.wav --model-type 3

エラーの切り分け

エラー 確認事項
GLIBCXX_x.x.xx not found GLIBCXX_3.4.29以上のC++ランタイム（Yocto 4.0以降のBSP）が必要です。BSPのバージョンを確認してください。
GLIBC_2.xx not found BSPのglibcとバイナリの要件を確認します。glibcのlibc.so.6やローダーを単体で上書きせず、対応するBSPを使用してください。
QnnSystem interface version mismatch QAIRT 2.47のYocto用ライブラリが選択されていることを確認します。
libcdsprpc.soの不足 / DSP初期化の失敗 BSPのFastRPC、CDSPファームウェア、デバイス権限、v68 skelの配置を確認します。
