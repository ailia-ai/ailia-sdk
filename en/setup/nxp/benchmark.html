NXP i.MX 95 Benchmarks

Detailed benchmarks comparing CPU and NPU execution of ailia SDK (NXP NPU build) and NXP ONNX Runtime on the NXP FRDM i.MX 95. For the summary and setup instructions, see the NXP i.MX 95 Setup Guide.

Measurement Conditions

We compared ailia SDK (NXP NPU build) with ONNX Runtime 1.24.3 (ORT) bundled with the NXP BSP on the FRDM i.MX 95. All models were measured on 2026-11-22 with ailia runtime c8e3d217e. All measurements use 6 CPU threads with profiling disabled, and NPU results include CPU execution of unsupported layers. Each backend uses the same model.

ORT was measured with its NPU CMA allocation fixed to 512 MiB. The tested board has 960 MiB of CMA, and ORT's default 2 GiB allocation fails and falls back to the CPU. ailia does not use this setting.

ViT-B/16 (Image Classification, 224×224)

Uses the INT4 model published in ailia-models (ViT-B_16-224-int4.onnx), which converts constant-weight MatMuls to MatMulNBits INT4 and runs the remaining operations in FP32. The input is images/vit/input.jpg bundled with the demo, batch 1. One dummy inference at model Open is excluded, and the table reports the median of the next 10 runs. Pre/post-processing and drawing are excluded.

ailia NPU is approximately 1.17x faster than ORT NPU. All four backends classified the image as Labrador retriever (ImageNet class 208) in all ten runs. A separate profiling run confirmed that all 72 MatMulNBits nodes run on Neutron with ORT NPU.

The 2026-11-18 measurement also compared the maximum absolute output difference when the same input is inferred repeatedly (output variation). Only ORT NPU varied (0.2002); ORT CPU, ailia CPU and ailia NPU were 0 (the same result every time).

In this model, the 347 fixed-weight MatMuls and the 109 MatMuls with two dynamic inputs are all converted to calibrated QuantizeLinear + MatMulInteger. ailia NPU runs the fixed-weight MatMuls on the NPU; because the MatMuls with two dynamic inputs are small, they run with NEON integer arithmetic on the CPU. Compared with the previous dynamic-quantization model, all seven horse detections are preserved, with a mean box IoU of 0.987 (minimum 0.978). This is an output comparison on the demo image, not a detection-accuracy (mAP) evaluation. ORT NPU outputs may vary between inferences.

Depth Anything V2 Metric Depth Small (Indoor Depth Estimation, 518×518)

Uses the COCO-calibrated depth-coco-val2017-conv-v4 model, with the first Bedroom frame (00000.jpg) as input. One dummy inference at model Open is excluded, and the table reports the median of the next 3 runs. Model loading, preprocessing and drawing are excluded.

ItemORT CPUORT NPUailia CPUailia NPU
Inference time (median)2,796.2 ms2,575.9 ms3,125.7 ms2,045.1 ms

In this model, the 48 fixed-weight MatMuls, 24 Attention MatMuls and 28 convolutions are converted to calibrated QuantizeLinear with MatMulInteger / ConvInteger, and ailia NPU runs them on the NPU. The three narrow, high-resolution output-head convolutions remain FP32 because they were slower on the NPU. Softmax and ConvTranspose also remain FP32. The ORT Neutron EP runs only the fixed-weight MatMuls on the NPU.

In an earlier comparison over the five Bedroom frames, the ailia CPU and ailia NPU outputs differed by 1.14 cm on average (23.84 cm maximum), the difference from ORT CPU was 4.55 cm on average (50.15 cm maximum), and the difference from the NPU model before convolution quantization was 4.90 cm on average (59.79 cm maximum). These are comparisons between outputs, not accuracy against ground-truth depth.

YOLOX-S (Object Detection, 320×320)

Uses the COCO-calibrated INT8 model (83 ConvInteger nodes), batch 1, with images/yolox/input.jpg bundled with the demo. One dummy inference at model Open is excluded, and the table reports the median of the next 10 runs. Preprocessing, NMS and drawing are excluded.

ItemORT CPUORT NPUailia CPUailia NPU
Inference time (median)793.9 ms795.7 ms436.9 ms114.8 ms
FPS1.261.262.298.71

The CPU figures measure the same ConvInteger model, not an optimized FP32 model. ailia's CPU execution uses tiled NEON INT8 kernels with cached fixed weights. The ORT Neutron EP runs ConvInteger on the CPU, so ORT NPU takes about the same time as ORT CPU. ailia NPU requantizes the outputs of supported operations on the NPU. This uses different rounding from CPU execution, so outputs are not bit-identical to the CPU.

On all 5,000 COCO val2017 images, AP is 29.00 for INT8 (ailia NPU) versus 30.42 for FP32 (host ORT CPU), a decrease of 1.42 points. The evaluation images are the same as the calibration data, so this is not accuracy on an independent test set.
