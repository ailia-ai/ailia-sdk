NXP i.MX 95 Setup Guide

How to set up ailia SDK on the NXP FRDM i.MX 95 and run inference on the CPU, GPU (Vulkan) and NPU (Neutron).

Overview

The NXP i.MX 95 is an application processor for industrial and automotive use with an Arm Cortex-A55 CPU, an Arm Mali-G310 GPU and an NXP eIQ Neutron NPU. This page explains how to set up ailia SDK on Yocto Linux on the FRDM i.MX 95 development board, how to run models, and the benchmark results.

Board Setup

For connecting power and USB serial, writing the Linux image to a microSD card, and booting and logging in, see FRDM i.MX 95 Board Setup.

Installing ailia SDK

With Ethernet connected, install ailia SDK from pip. The AArch64 wheel (manylinux2014_aarch64) is selected automatically.

pip3 install ailia

After installation, list the available execution environments.

python3 -c "import ailia; [print(i, ailia.get_environment(i)) for i in range(ailia.get_environment_count())]"
0 CPU
1 VulkanDNN-Mali-G310 (FP32)
2 VulkanDNN-Mali-G310 (FP16)
Note: The pip libailia.so actually requires only up to GLIBC 2.27 / GLIBCXX 3.4.22, so it runs as-is on i.MX 95 Yocto (glibc 2.43).

Getting the License

The pip version downloads an evaluation license automatically on the first inference. If the board has no IPv6 default route, the connection to the license server can fail with OSError: [Errno 101] Network is unreachable. In that case, download it over IPv4 explicitly.

mkdir -p ~/.shalo
curl -4 -fL https://axip-console.appspot.com/license/download/product/AILIA -o ~/.shalo/AILIA.lic

Also make sure the system clock is set correctly.

Installing the NPU (Neutron) Build

To use the Neutron NPU, use the ailia SDK NXP NPU build. It is distributed in the ailia-sdk-nxp-demo repository. After installing the pip version, replace libailia.so in the package with the NXP NPU build.

git clone https://github.com/ailia-ai/ailia-sdk-nxp-demo.git
cd ailia-sdk-nxp-demo
python3 scripts/copy_sdk.py --install-npu

Close any application that uses ailia before replacing the file.

Note: The NXP NPU build is built for NXP i.MX Distro 6.18-wrynose (it depends on GLIBC_2.43 and others). On older BSPs, replacing the library alone is not enough.

After replacing the files, Neutron-i.MX95-NPU is added to the environment list when /dev/neutron0 and libNeutronDriver.so are found. On devices without the NPU or the Neutron driver, only CPU and Vulkan are listed.

python3 -c "import ailia; [print(i, ailia.get_environment(i)) for i in range(ailia.get_environment_count())]"

To run on the NPU, use a model in which MatMuls with constant weights are converted to MatMulNBits (INT4) (see Creating Models for the NPU). Nodes the NPU does not support run on the CPU automatically. Weights are converted for the NPU on the first inference, so only the first run takes longer.

Architecture

ailia SDK takes ONNX as input, parses the graph and instantiates layers. Layers that can run on the NPU (MatMulNBits, MatMulInteger, ConvInteger, static QDQ matrix multiplications, etc.) are replaced with NPU segments when the model is loaded, and the other layers run on ailia_cpu. NPU segments do not go through an ONNX Runtime or TFLite Execution Provider; they call the low-level API of libNeutronDriver.so in the BSP directly. libNeutronDriver.so is loaded at runtime with dlopen, so on devices without the NPU there is no link error and only CPU and Vulkan are used.

APIs Used

ailia obtains and uses the following functions from libNeutronDriver.so.

FunctionPurpose
allocateBuffer / releaseBufferAllocate and release a CMA region the NPU can access
tiling_solver / weight_packer / compress_weight_tensor, etc.Convert (pack) and compress weights into the NPU tile format
clean_cacheWrite back the CPU data cache to keep data consistent between the NPU and CPU
matmulRun a matrix multiplication on the NPU (synchronous call that waits for completion)

Memory

The i.MX 95 Neutron NPU shares the same DRAM as the Arm CPU. ailia allocates one physically contiguous 512 MiB CMA region with allocateBuffer and receives it as a pointer mapped into the process address space. The CPU reads and writes this region directly and the NPU accesses the same physical memory, so there is no transfer to device memory as with a PCIe GPU.

  • First 320 MiB: data kept for the session, such as packed weights
  • Last 192 MiB: per-inference work area, such as quantized inputs, INT32 outputs and the matrix multiplication settings (header)

The settings header records the locations of the weights, inputs and outputs as offsets within the same region. ailia writes back data written by the CPU with clean_cache before calling matmul, and after completion it maintains the cache for the output region before reading it on the CPU. Because the region is shared by multiple models, NPU executions are serialized with a lock.

Creating Models for the NPU

Basic Configuration: FP32 + NPU (INT8 MMA)

Using the NPU does not require quantizing the whole model to INT8. The basic configuration keeps the model in FP32 and converts only MatMuls with constant weights (fully connected layers) to MatMulNBits (INT4 weights). The converted MatMulNBits nodes run on the NPU as INT8 multiply-accumulate (MMA), and the other layers stay FP32 and run on the CPU.

OperationFormat in the modelWhere it runs and precision
MatMul with constant weights (Attention Q/K/V and output projections, MLP, etc.)MatMulNBits (INT4 weights)NPU: inputs are dynamically quantized to INT8, INT8 × INT8 is accumulated in INT32 and converted back to FP32
LayerNorm, Softmax, GELU, residual AddFP32CPU: FP32
MatMul between activations, such as Attention QK / AVFP32CPU: FP32

This configuration has the following advantages:

  • No calibration: only the weights are quantized (weight-only) and inputs are quantized dynamically at each inference, so no calibration dataset is needed.
  • Accuracy is easy to keep: LayerNorm and Softmax, which are sensitive to quantization, are computed in FP32. For ViT-B/16, the top-5 ranking matched between FP32 and INT4.
  • Small models: weights become 4 bit, so ViT-B/16 shrinks from 330.3 MiB to 49.3 MiB.

MatMulNBits supports only 4-bit weights. To quantize weights to 8 bits, use DynamicQuantizeLinear + MatMulInteger instead of MatMulNBits. Quantizing MatMul with ONNX Runtime's quantize_dynamic produces a model in this form. Inputs are still quantized dynamically at each inference, so no calibration is needed.

from onnxruntime.quantization import quantize_dynamic, QuantType

quantize_dynamic(
    "ViT-B_16-224.onnx",
    "ViT-B_16-224-int8.onnx",
    op_types_to_quantize=["MatMul"],
    weight_type=QuantType.QInt8,
)

The layers that ailia SDK and NXP ONNX Runtime (Neutron Execution Provider) run on the NPU are listed below. In both, nodes that do not meet the conditions run on the CPU.

With NXP ONNX Runtime, when we ran static QDQ models (ViT, ResNet-50) with the Neutron EP, all matrix multiplications and convolutions (QLinearMatMul, QGemm, QLinearConv) ran on the CPU, and the NPU gave no speedup.

Converting to MatMulNBits

Convert on a PC with ONNX Runtime's MatMulNBitsQuantizer. The ViT export sample in ailia-models (image_classification/vit/export/export_int4.py) is a good reference. The sample will be added in ailia-models PR #1966. For how MatMulNBits works, see MatMulNBits: 4-bit quantization for running LLMs and VLMs with ONNX (Japanese).

pip3 install onnxruntime onnx numpy
cd ailia-models/image_classification/vit/export
python3 export_int4.py

It downloads the FP32 model, converts it to MatMulNBits, and writes ViT-B_16-224-int4.onnx and the .prototxt for ailia. The core of the conversion is:

import onnx
from onnxruntime.quantization.matmul_nbits_quantizer import MatMulNBitsQuantizer
from onnxruntime.quantization.quant_utils import QuantFormat

model = onnx.load("ViT-B_16-224.onnx")
quantizer = MatMulNBitsQuantizer(
    model=model,
    block_size=128,
    is_symmetric=True,
    accuracy_level=4,
    quant_format=QuantFormat.QOperator,
    op_types_to_quantize=("MatMul",),
)
quantizer.process()
onnx.save(quantizer.model.model, "ViT-B_16-224-int4.onnx")
ParameterValueMeaning
op_types_to_quantize("MatMul",)Convert only MatMul. MatMuls without constant weights (Attention QK / AV) automatically stay FP32.
block_size128Size of the weight blocks that share a scale
is_symmetricTrueSymmetric quantization without a zero point. The NPU does not support zero points.
accuracy_level4Quantize inputs to INT8 and accumulate in INT32
quant_formatQOperatorOutput as MatMulNBits nodes

For ViT-B/16, 72 MatMuls with constant weights become MatMulNBits, while the 24 Attention MatMuls and the classification-head Gemm stay FP32.

MatMulNBits nodes run on the NPU when K is a multiple of 16, N is a multiple of 128, and there is no zero point. Nodes that do not meet these conditions run on the CPU automatically, without errors. You can check the converted model as follows.

import collections, onnx

model = onnx.load("ViT-B_16-224-int4.onnx")
print(collections.Counter(n.op_type for n in model.graph.node))
for node in model.graph.node:
    if node.op_type == "MatMulNBits":
        a = {x.name: onnx.helper.get_attribute_value(x) for x in node.attribute}
        ok = a["bits"] == 4 and a["K"] % 16 == 0 and a["N"] % 128 == 0 and len(node.input) <= 3
        print(node.name, a["K"], a["N"], "OK" if ok else "CPU")

Generate the .prototxt that ailia loads with onnx2prototxt.py from export-to-onnx (the export sample generates it automatically).

python3 onnx2prototxt.py ViT-B_16-224-int4.onnx

Running Models

Use the samples in ailia-models. Specify the execution environment ID with the -e option.

git clone https://github.com/ailia-ai/ailia-models.git
cd ailia-models
pip3 install -r requirements.txt
cd image_classification/vit

# CPU
python3 vit.py -e 0
# Vulkan (Mali-G310 FP16)
python3 vit.py -e 2
# Benchmark mode (11 inferences)
python3 vit.py -e 0 -b -bc 11

To run on the NPU, use the INT4 (MatMulNBits) model and pass the ID of Neutron-i.MX95-NPU to -e. The INT4 option for ViT will be added in ailia-models PR #1966.

python3 vit.py --quantize int4 -e <ID of Neutron-i.MX95-NPU> -b -bc 11
Note: When running from the serial console, save the result to an image file, for example with -s output.png.

Benefits of Using ailia

NPU Results That Do Not Change Between Runs

With NXP ONNX Runtime on Neutron, we confirmed that ViT and SAM 2.1 outputs change from run to run for the same input. ailia achieves zero output variation by splitting large matrices into sizes the NPU processes reliably. This suits products that need reproducibility, such as threshold decisions and regression testing.

Fast on Transformer Models

In addition to MatMulNBits on the NPU, ARM NEON INT4 CPU kernels and the Whisper KV cache gave measured speeds of 1.08x ONNX Runtime for ViT, 1.85x for Whisper large-v3-turbo and 2.2x for the SAM 2.1 Image Encoder. Session creation is also fast: 2.0 seconds for SAM 2.1 compared with 4.2 seconds for ONNX Runtime on the NPU.

No Dependency on ONNX Runtime or TFLite

ailia calls the low-level API of libNeutronDriver.so directly and manages node selection, weight packing, CMA memory and CPU fallback itself. The Neutron driver is loaded at runtime, so the same binary runs on CPU / Vulkan on i.MX devices without the NPU and on other Linux devices.

Switch Between CPU, GPU and NPU with the Same API

Changing the environment ID runs the same model and code on the CPU, Mali-G310 (Vulkan) or the Neutron NPU. The C++ / Python / C# / Flutter API is shared with Windows, macOS, Linux, Android and iOS, so applications developed on a PC can be ported to the i.MX 95 as-is.

400+ Models with Pre- and Post-processing

You can try more than 400 models from ailia-models on the i.MX 95. Combined with libraries such as ailia Speech (Whisper), ailia Tokenizer and ailia LLM, you can build speech recognition and generative AI into embedded devices.
