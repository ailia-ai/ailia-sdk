Creating Models for the NPU

How to create ONNX models that run on the NXP i.MX 95 Neutron NPU, with examples: ViT-B/16, SAM 2.1 Tiny, Grounding DINO, Depth Anything V2 and YOLOX-S. For setting up ailia SDK, see the NXP i.MX 95 Setup Guide.

Choosing a Conversion Method

The Neutron NPU executes INT8 matrix multiplications. A model for the NPU is created by converting the matrix multiplications and convolutions of an FP32 ONNX model into the standard ONNX integer operators that ailia SDK can offload (MatMulNBits, MatMulInteger and ConvInteger). The conversion methods are as follows.

MethodTarget operatorsCalibrationOn this page
INT4 weight-only quantizationMatMulNBits (INT4 weights)Not requiredExample 1: ViT-B/16
INT8 dynamic quantizationDynamicQuantizeLinear + MatMulIntegerNot requiredINT8 Dynamic Quantization
INT8 static quantization (MatMul)QuantizeLinear + MatMulIntegerRequired (calibration dataset)Example 2: SAM 2.1 Tiny, Example 3: Grounding DINO and Depth Anything V2
INT8 static quantization (convolution)QuantizeLinear + ConvIntegerRequired (calibration dataset)Example 4: YOLOX-S

When in doubt, start with INT4 weight-only quantization: it needs no calibration, keeps accuracy well, and suits the fully connected layers of Transformer models. Use static quantization of MatMuls when you also want to run matrix multiplications with two dynamic inputs, such as Attention QK / AV, as integer operations. To run CNN convolutions on the NPU, use static quantization of convolutions. With any method, there is no need to quantize the whole model: nodes that do not meet the conditions automatically run on the CPU in FP32.

Layers That Run on the NPU

The layers that ailia SDK and NXP ONNX Runtime (Neutron Execution Provider) run on the NPU are listed below. In both, nodes that do not meet the conditions run on the CPU.

RuntimeLayerConditions
ailia SDKMatMulNBitsINT4 / INT8, no zero point, constant weights and scales, K % 16 == 0. INT8 requires block_size >= K
MatMulIntegerUINT8 input and INT8 / UINT8 weights. Supports constant and dynamic weights, scalar zero points, and fusion of Cast, constant scales, bias and UINT8 requantization
ConvInteger1D / 2D, group 1, UINT8 input and constant INT8 / UINT8 weights. Supports stride, dilation, automatic padding, scalar / channel-wise weight zero points, and fusion of the following scale, bias, activation (LUT, such as Swish) and UINT8 requantization
NXP ONNX RuntimeMatMulNBits4 bit, no zero point, constant weights, K % 16 == 0, N % 128 == 0
MatMulInteger, MatMulIntegerToFloat, QLinearMatMul, QGemmConstant weights, N % 16 == 0

The ailia SDK NPU frontend does not offload static QDQ patterns (DequantizeLinear → MatMul / Conv) directly. When using a QDQ model, convert the target operations offline to MatMulInteger or ConvInteger while preserving the quantized tensors, scales, zero points and multiplication order (see Examples 2 to 4). Nodes that do not meet the conditions run on the CPU.

Example 1: ViT-B/16 — INT4 Weight-Only Quantization (MatMulNBits)

Basic Configuration: FP32 + NPU (INT8 MMA)

Using the NPU does not require quantizing the whole model to INT8. The basic configuration keeps the model in FP32 and converts only MatMuls with constant weights (fully connected layers) to MatMulNBits (INT4 weights). The converted MatMulNBits nodes run on the NPU as INT8 multiply-accumulate (MMA), and the other layers stay FP32 and run on the CPU.

OperationFormat in the modelWhere it runs and precision
MatMul with constant weights (Attention Q/K/V and output projections, MLP, etc.)MatMulNBits (INT4 weights)NPU: inputs are dynamically quantized to INT8, INT8 × INT8 is accumulated in INT32 and converted back to FP32
LayerNorm, Softmax, GELU, residual AddFP32CPU: FP32
MatMul between activations, such as Attention QK / AVFP32CPU: FP32

This configuration has the following advantages:

  • No calibration: only the weights are quantized (weight-only) and inputs are quantized dynamically at each inference, so no calibration dataset is needed.
  • Accuracy is easy to keep: LayerNorm and Softmax, which are sensitive to quantization, are computed in FP32. For ViT-B/16, the top-5 ranking matched between FP32 and INT4.
  • Small models: weights become 4 bit, so ViT-B/16 shrinks from 330.3 MiB to 49.3 MiB.

Converting to MatMulNBits

Convert on a PC with ONNX Runtime's MatMulNBitsQuantizer. The ViT export sample in ailia-models, image_classification/vit/export/export_int4.py, is a good reference. For how MatMulNBits works, see MatMulNBits: 4-bit quantization for running LLMs and VLMs with ONNX (Japanese).

pip3 install onnxruntime onnx numpy
cd ailia-models/image_classification/vit/export
python3 export_int4.py

It downloads the FP32 model, converts it to MatMulNBits, and writes ViT-B_16-224-int4.onnx and the .prototxt for ailia. The core of the conversion is:

import onnx
from onnxruntime.quantization.matmul_nbits_quantizer import MatMulNBitsQuantizer
from onnxruntime.quantization.quant_utils import QuantFormat

model = onnx.load("ViT-B_16-224.onnx")
quantizer = MatMulNBitsQuantizer(
    model=model,
    block_size=128,
    is_symmetric=True,
    accuracy_level=4,
    quant_format=QuantFormat.QOperator,
    op_types_to_quantize=("MatMul",),
)
quantizer.process()
onnx.save(quantizer.model.model, "ViT-B_16-224-int4.onnx")
ParameterValueMeaning
op_types_to_quantize("MatMul",)Convert only MatMul. MatMuls without constant weights (Attention QK / AV) automatically stay FP32.
block_size128Size of the weight blocks that share a scale
is_symmetricTrueSymmetric quantization without a zero point. The NPU does not support zero points.
accuracy_level4Quantize inputs to INT8 and accumulate in INT32
quant_formatQOperatorOutput as MatMulNBits nodes

For ViT-B/16, 72 MatMuls with constant weights become MatMulNBits, while the 24 Attention MatMuls and the classification-head Gemm stay FP32.

Checking the Converted Model

MatMulNBits nodes run on the NPU when K is a multiple of 16, N is a multiple of 128, and there is no zero point. Nodes that do not meet these conditions run on the CPU automatically, without errors. You can check the converted model as follows.

import collections, onnx

model = onnx.load("ViT-B_16-224-int4.onnx")
print(collections.Counter(n.op_type for n in model.graph.node))
for node in model.graph.node:
    if node.op_type == "MatMulNBits":
        a = {x.name: onnx.helper.get_attribute_value(x) for x in node.attribute}
        ok = a["bits"] == 4 and a["K"] % 16 == 0 and a["N"] % 128 == 0 and len(node.input) <= 3
        print(node.name, a["K"], a["N"], "OK" if ok else "CPU")

Generate the .prototxt that ailia loads with onnx2prototxt.py from export-to-onnx (the export sample generates it automatically).

python3 onnx2prototxt.py ViT-B_16-224-int4.onnx

INT8 Dynamic Quantization (MatMulInteger)

For 8-bit weights, the recommended form is the standard ONNX DynamicQuantizeLinear + MatMulInteger graph. Quantizing MatMul with ONNX Runtime's quantize_dynamic produces a model in this form. Inputs are still quantized dynamically at each inference, so no calibration is needed. ailia SDK can also handle INT8 MatMulNBits, but NPU offload is limited to one block per output channel (block_size >= K) and is disabled by default.

from onnxruntime.quantization import quantize_dynamic, QuantType

quantize_dynamic(
    "ViT-B_16-224.onnx",
    "ViT-B_16-224-int8.onnx",
    op_types_to_quantize=["MatMul"],
    weight_type=QuantType.QInt8,
)

Example 2: SAM 2.1 Tiny — Static Quantization (MatMulInteger)

To run more operations as integer arithmetic, including matrix multiplications with two dynamic inputs such as Attention QK / AV, use static quantization with a calibration dataset. After quantizing to the QDQ format, convert the target MatMuls to standard ONNX MatMulInteger while preserving the quantized tensors and scales. Because ailia can run MatMulInteger with two dynamic inputs on the NPU, the Attention matrix multiplications are also offloaded.

The COCO-calibrated SAM 2.1 Tiny model used in the i.MX 95 benchmarks is generated with scripts/calibrate_sam2.py in ailia-sdk-nxp-demo. The converted models are bundled in the repository's models/ directory, so no conversion is needed to try them first. To generate them yourself, prepare the published SAM 2.1 Tiny ONNX exports from SAM 2 in ailia-models and the COCO 2017 validation images and annotations, and run on a host PC:

git clone https://github.com/ailia-ai/ailia-sdk-nxp-demo.git
cd ailia-sdk-nxp-demo
python3 -m pip install -r scripts/requirements-calibration.txt
python3 scripts/calibrate_sam2.py \
  --source-dir /path/to/ailia-models/image_segmentation/segment-anything-2 \
  --download-sources \
  --coco-images /path/to/coco/val2017 \
  --coco-annotations /path/to/coco/annotations/instances_val2017.json \
  --output /path/to/sam2-calibrated \
  --workers 2 --threads 2

Calibration uses Min/Max over all 5,000 images of COCO val2017; activations are quantized to tensor-wise UINT8 and constant weights to channel-wise INT8. Memory Attention is calibrated with 5-frame pseudo-videos generated from each image.

The generated models mix INT8 and FP32. As in Example 1, operations that are sensitive to quantization stay FP32.

  • Image Encoder: MatMuls are converted to integer arithmetic. Convs remain QDQ, and Softmax / LayerNorm quantize only their inputs and outputs.
  • Memory Attention: MatMuls (including Attention QK / AV) are converted to integer arithmetic, and RoPE stays FP32.
  • Other auxiliary models: remain FP32.

The step that lowers QDQ MatMul pairs to MatMulInteger is a standalone script, scripts/convert_qdq_matmul.py, and can be applied to your own QDQ models. It preserves the scales and quantized tensors and performs no requantization. Integer accumulation changes floating-point rounding, so validate the model outputs before deploying the converted model.

Calibration records (manifest.json, ranges_*.json and completion.json) are saved in the output directory, and an interrupted conversion resumes when you run the same command again. The calibration records for the models bundled with the demo are in the repository's calibration/ directory. The scripts in Examples 3 and 4 work the same way.

Example 3: Grounding DINO and Depth Anything V2 — Static Quantization of Fixed-Weight MatMuls

For large Transformer models, another effective configuration statically quantizes only the constant-weight MatMuls to MatMulInteger and leaves the other operations in FP32. Activations are quantized to tensor-wise UINT8 and weights to channel-wise INT8, expressed with standard ONNX QuantizeLinear / MatMulInteger / Cast / Mul nodes. Both models are calibrated with global Min/Max over all 5,000 images of COCO val2017.

Grounding DINO Swin-T (400×599)

Convert the published groundingdino_swint_ogc.onnx from Grounding DINO in ailia-models.

curl --fail --location --output groundingdino_swint_ogc.onnx \
  https://storage.googleapis.com/ailia-models/groundingdino/groundingdino_swint_ogc.onnx
python3 scripts/calibrate_grounding.py \
  --source groundingdino_swint_ogc.onnx \
  --coco-images /path/to/coco/val2017 \
  --coco-annotations /path/to/coco/annotations/instances_val2017.json \
  --output /path/to/grounding-calibrated \
  --workers 3 --threads 3
  • The input model is promoted to FP32 before activation ranges are collected. The 80 COCO category names are used as the text prompt, and image preprocessing and tokenization are shared with the demo.
  • The 347 fixed-weight MatMuls are converted to MatMulInteger; other operations remain FP32.
  • The graph is rearranged so that ailia SDK's DeformableAttention fusion can be used.
  • The output is models/groundingdino_swint_ogc_400x599_int8.onnx with external weight files (.dataNN). Keep the ONNX file and the weight files in the same folder.

Depth Anything V2 Metric Depth Small (518×518)

Convert the indoor (Hypersim) Small model from ailia-models.

curl -fL https://storage.googleapis.com/ailia-models/depth_anything_v2/depth_anything_v2_metric_hypersim_vits.onnx \
  -o /path/to/depth_anything_v2_metric_hypersim_vits.onnx
python3 scripts/calibrate_depth.py \
  --source /path/to/depth_anything_v2_metric_hypersim_vits.onnx \
  --coco-images /path/to/coco/val2017 \
  --coco-annotations /path/to/coco/annotations/instances_val2017.json \
  --output /path/to/depth-calibrated
  • The input is fixed to 518×518, and the 48 fixed-weight MatMuls are converted to MatMulInteger.
  • The 24 dynamic Attention MatMuls remain FP32 in the model. On the ailia NPU, the runtime quantizes them to INT8 at inference time and runs them on the NPU. Softmax and convolutions run on the CPU.
  • Use depth_anything_v2_metric_hypersim_vits_518_int8.onnx after completion.json confirms that all 5,000 images were processed.

Example 4: YOLOX-S 320 — Static Quantization of Convolutions (ConvInteger)

For CNNs, convert convolutions to standard ONNX ConvInteger to run them on the NPU. ailia SDK fuses 2D ConvInteger with the following scale, bias and activation on the NPU side and writes UINT8 feature maps directly. Calibrate YOLOX-S (yolox_s.opt.onnx) from ailia-models with Min/Max over all 5,000 images of COCO val2017.

curl -L https://storage.googleapis.com/ailia-models/yolox/yolox_s.opt.onnx -o yolox_s.opt.onnx
python3 scripts/calibrate_yolox.py \
  --source yolox_s.opt.onnx \
  --coco-images /path/to/val2017 \
  --coco-annotations /path/to/annotations/instances_val2017.json \
  --output models/yolox_s_320_int8.onnx \
  --report calibration/yolox/report.json
  • The 83 convolutions are converted to ConvInteger. Weights are channel-wise INT8 and feature maps are UINT8.
  • The scale, bias and Swish after each convolution remain standard ONNX FLOAT operations, which the ailia Neutron backend fuses and writes out as UINT8. Swish is computed with a lookup table (LUT).
  • The final detection formatting remains FP32.
  • ailia NPU requantizes the outputs of supported operations on the NPU. This uses different rounding from CPU execution, so outputs are not bit-identical to the CPU.

On all 5,000 COCO val2017 images, AP is 29.00 for INT8 (ailia NPU) versus 30.42 for FP32 (host ORT CPU), a decrease of 1.42 points. The evaluation images are the same as the calibration data, so this is not accuracy on an independent test set.
