ailia LLM Tool Use Guide

How to use Gemma 4 function calling (tool use) with ailia LLM: declaring tools in the system prompt, the format of the model output, and how to parse it.

Overview

Gemma 4 supports native function calling, in which tool (function) declarations, tool calls and tool results are expressed with dedicated control tokens. The ailia LLM API has no argument for passing tool definitions, but Gemma 4 control tokens are tokenized as special tokens simply by including them as text in the prompt. Tool use is therefore implemented by writing the tool declarations in the system prompt and parsing the model output on the application side.

This page is based on Google's Gemma 4 function calling documentation and on the Agent mode of ailia Insight, a reference implementation built on ailia LLM.

Supported Models

  • Gemma 4 E2B / E4B / 26B-A4B / 31B (GGUF)
Note: The control token format is specific to Gemma 4. Other models require the format defined by their own chat template.

Overall Flow

Tool use is a loop: the model emits a tool call, the application runs the tool and returns the result, and the model generates the final answer.

System prompt
Tool descriptions + call format instructions + <|tool> declarations
↓
ailia LLM (Gemma 4)
ailiaLLMSetPrompt → ailiaLLMGenerate
↓
Parse the output
Tool call if <|tool_call> is present, otherwise the final answer
↓

Execute the function on the application side
↓
Append the result and regenerate
Add <|tool_response> to the conversation and call ailiaLLMGenerate again

Control Tokens

Gemma 4 tool use relies on the following control tokens. Opening tokens have the form <|name> and closing tokens <name|>.

TokenPurposeFormat
<|tool> … <tool|>Tool declaration (system prompt)<|tool>declaration:name{...}<tool|>
<|tool_call> … <tool_call|>Tool call (model output)<|tool_call>call:name{args}<tool_call|>
<|tool_response> … <tool_response|>Tool result (returned by the application)<|tool_response>response:name{result}<tool_response|>
<|"|>String value quotekey:<|"|>value<|"|>
<|channel> … <channel|>Thinking (reasoning)Prepended to the output; not part of the answer

Arguments and results are comma-separated key:value pairs. Strings are wrapped in <|"|>, while numbers and booleans are written without quotes, such as cursor:0 and literal:true. Unlike JSON, keys are not quoted.

Declaring Tools in the System Prompt

The Gemma 4 chat template expands tool declarations inside the system turn as <|tool>declaration:...<tool|>. With ailia LLM, write this declaration string directly at the end of the system prompt. The declaration format is shown below (the JSON Schema content is written in Gemma 4 notation, with type in upper case such as STRING, INTEGER, BOOLEAN and OBJECT).

<|tool>declaration:get_current_temperature{description:<|"|>Gets the current temperature for a given location.<|"|>,parameters:{properties:{location:{description:<|"|>The city name, e.g. San Francisco<|"|>,type:<|"|>STRING<|"|>}},required:[<|"|>location<|"|>],type:<|"|>OBJECT<|"|>}}<tool|>

ailia Insight includes not only the declarations but also natural-language tool descriptions and call format instructions in the system prompt, because declarations alone do not reliably make the model follow the argument types and quoting rules. The following four parts are joined with blank lines.

  1. The base system prompt (the assistant's role)
  2. The tool list and usage rules (one tool call per response, final answer only after everything is done, etc.), plus each tool's description, parameters and call examples
  3. Call format instructions (see below)
  4. <|tool> declarations
You are a helpful AI assistant with access to tools.

Rules:
1. Use exactly ONE tool call per response. Never call multiple tools at once.
2. After each tool response, decide the next step and either call another tool or provide the final answer.
3. Do NOT give your final answer until every part of the user's request is fulfilled.
4. When all steps are done, give your final answer as plain text.

### Available tools

- read_file_chunk: Read a chunk of text from a local file. Use cursor "0" for the first chunk, then pass the returned next_cursor to continue until eof is true.
  Parameters: {path:<|"|>...<|"|>,cursor:<|"|>...<|"|>,max_chars:<|"|>...<|"|>}
path: Local file path to read. (string, required).
cursor: Opaque cursor. Use 0 first, then reuse returned next_cursor. (integer, required). minimum 0.
max_chars: Maximum text characters to return. Use 12000 by default. (integer, optional). minimum 1.
  Examples:
  - Read the first chunk of a local text file.
    <|tool_call>call:read_file_chunk{path:<|"|>/home/user/file.txt<|"|>,cursor:0,max_chars:12000}<tool_call|>

Tool call format for this provider:
To call a tool, output exactly:
<|tool_call>call:TOOL_NAME{PARAM:<|"|>VALUE<|"|>}<tool_call|>

Every string value in tool calls must be wrapped with <|"|> on both sides. Integer and boolean values may be written without quotes, such as cursor:0 and literal:true. Multi-line string values are allowed inside <|"|>...<|"|>. To give your final answer, respond with plain text without tool_call tags.

<|tool>declaration:read_file_chunk{description:<|"|>Read a chunk of text from a local file. ...<|"|>,parameters:{path:<|"|>...<|"|>,cursor:<|"|>...<|"|>,max_chars:<|"|>...<|"|>}
path: Local file path to read. (string, required).
cursor: Opaque cursor. Use 0 first, then reuse returned next_cursor. (integer, required). minimum 0.
max_chars: Maximum text characters to return. Use 12000 by default. (integer, optional). minimum 1.}<tool|>
Note: In ailia Insight the JSON Schema is the single source of truth for tool definitions, and the parameter description for Gemma 4 (types, required flags and minimum values written as sentences) is generated from the schema. Because the notation is weakly typed, integer and boolean constraints are expressed in the description text.

The system prompt is passed as a regular system role message. ailia LLM parses special tokens when tokenizing the prompt, so tokens such as <|tool> become control tokens simply by being included as text.

import ailia_llm

model = ailia_llm.AiliaLLM()
model.open("gemma-4-E2B-it-Q4_K_M.gguf")

messages = [
    {"role": "system", "content": system_prompt},   # system prompt including tool declarations
    {"role": "user", "content": "Read the beginning of /home/user/file.txt and summarize it."},
]
response = "".join(model.generate(messages))

Model Output

When the model decides to use a tool, its output contains a <|tool_call> block.

<|tool_call>call:read_file_chunk{path:<|"|>/home/user/file.txt<|"|>,cursor:0,max_chars:12000}<tool_call|>

When thinking is enabled (ailiaLLMSetThinking), the reasoning is prepended.

<|channel>The user wants a summary of a file, so I should read it first.<channel|><|tool_call>call:read_file_chunk{path:<|"|>/home/user/file.txt<|"|>,cursor:0,max_chars:12000}<tool_call|>

When no tool is needed, plain text without control tokens is returned. Treat it as the final answer.

The output is classified as follows.

OutputInterpretationNext action
Contains <|tool_call>...<tool_call|>Tool callParse the arguments, run the tool, return the result and regenerate
Plain text without control tokensFinal answerShow it to the user and stop
Thinking only, no bodyThought onlyAdd a message asking for an answer and regenerate
Empty or malformedParse errorReturn the expected format as an error and regenerate

Parsing the Output

Parsing is done in three steps.

  1. Separate thinking: Remove the span from <|channel> to <channel|>. Even with thinking disabled the model sometimes emits only the closing token <channel|>; in that case treat everything before it as thinking, unless a <|tool_call> appears before it, in which case leave the text as is.
  2. Extract the tool call: Use the regular expression <\|tool_call>call:(\w+)\{(.*)\}<tool_call\|> (DOTALL) to get the tool name and the argument string.
  3. Decode the arguments: Parse the argument string as comma-separated key:value pairs. A value starting with <|"|> is read as a string up to the next <|"|>; other values are interpreted as numbers or booleans.

To include a literal \ or <|"|> inside a string value, escape it with a backslash as \\ or <|\"|>. Strings may contain newlines. Because string values can contain commas, do not simply split(","); scan from the start while honoring the quotes.

import re

QUOTE = '<|"|>'
TOOL_CALL = re.compile(r'<\|tool_call>call:(\w+)\{(.*)\}<tool_call\|>', re.DOTALL)

def extract_thinking(text):
    start = text.find('<|channel>')
    if start < 0:
        end = text.find('<channel|>')
        if end < 0 or '<|tool_call>' in text[:end]:
            return None, text
        return text[:end].strip(), text[end + len('<channel|>'):].strip()
    end = text.find('<channel|>', start)
    if end < 0:
        return text[start + len('<|channel>'):].strip(), text[:start].strip()
    thinking = text[start + len('<|channel>'):end].strip()
    return thinking, (text[:start] + text[end + len('<channel|>'):]).strip()

def parse_bare(value):
    low = value.lower()
    if low == 'true': return True
    if low == 'false': return False
    try: return int(value)
    except ValueError: pass
    try: return float(value)
    except ValueError: return value

def decode_args(src):
    result, i, n = {}, 0, len(src)
    while i < n:
        while i < n and src[i].isspace(): i += 1
        m = re.compile(r'\w+').match(src, i)
        if not m: return None
        key, i = m.group(0), m.end()
        while i < n and src[i].isspace(): i += 1
        if i >= n or src[i] != ':': return None
        i += 1
        while i < n and src[i].isspace(): i += 1
        if src.startswith(QUOTE, i):                      # string value
            i += len(QUOTE); buf = []
            while i < n and not src.startswith(QUOTE, i):
                if src[i] == '\\' and i + 1 < n and src[i + 1] in ('\\', '"'):
                    buf.append(src[i + 1]); i += 2
                else:
                    buf.append(src[i]); i += 1
            if i >= n: return None                        # missing closing quote
            i += len(QUOTE)
            result[key] = ''.join(buf)
        else:                                            # number / boolean
            j = src.find(',', i)
            j = n if j < 0 else j
            result[key] = parse_bare(src[i:j].strip()); i = j
        while i < n and src[i].isspace(): i += 1
        if i < n:
            if src[i] != ',': return None
            i += 1
    return result or None

def parse_response(text):
    thinking, body = extract_thinking(text)
    m = TOOL_CALL.search(body)
    if m:
        return {"type": "tool_call", "name": m.group(1),
                "args": decode_args(m.group(2)), "thinking": thinking}
    if body.strip():
        return {"type": "final_answer", "content": body.strip()}
    if thinking:
        return {"type": "thought", "content": thinking}
    return {"type": "parse_error"}
Note: For streaming display, remove complete <|tool_call>...<tool_call|> and <|tool_response>...<tool_response|> blocks from the displayed text, and also hide everything after a trailing opening token that has not been closed yet.

Returning Tool Results

After running the tool, wrap the result in a <|tool_response> block, add it to the conversation and generate again. The result has the form response:tool_name{...} with key-value pairs.

<|tool_response>response:read_file_chunk{result:<|"|>(file contents)<|"|>}<tool_response|>

Because the ailia LLM API has no tool role, ailia Insight concatenates the conversation history (user message, the model's tool calls and the tool results) as text in order, and sends it as a single user message together with the system prompt. Previous tool calls by the model are written back into the history in their <|tool_call> form.

Read the beginning of /home/user/file.txt and summarize it.
<|tool_call>call:read_file_chunk{path:<|"|>/home/user/file.txt<|"|>,cursor:0,max_chars:12000}<tool_call|>
<|tool_response>response:read_file_chunk{result:<|"|>{"text":"...","next_cursor":12000,"eof":true}<|"|>}<tool_response|>
history = user_message
while True:
    messages = [{"role": "system", "content": system_prompt},
                {"role": "user", "content": history}]
    step = parse_response("".join(model.generate(messages)))
    if step["type"] == "tool_call":
        output = run_tool(step["name"], step["args"])      # run the tool on the application side
        history += "\n" + build_tool_call(step["name"], step["args"])
        history += "\n" + build_tool_response(step["name"], output)
    elif step["type"] == "final_answer":
        print(step["content"]); break
    else:
        history += "\nError: Invalid input. Expected: <|tool_call>call:tool_name{param:<|"|>value<|"|>}<tool_call|>"

If the tool output contains <|"|> or \, escape it with the same rules as for arguments before wrapping it in <|"|>.

Implementation Notes

  • One tool call per response: Gemma 4 can emit multiple tool calls in parallel, but ailia Insight instructs the model in the system prompt to call one tool at a time to keep processing simple, and treats multiple calls as an error to retry.
  • Controlling thinking: Enabling thinking with ailiaLLMSetThinking improves the decision of whether and how to call tools, at the cost of generation time. Even when disabled, the model may write its reasoning as plain text, which cannot be distinguished from a plain final answer, so adding an instruction at the top of the system prompt such as "do not write out your reasoning; respond with exactly one tool call or the final answer only" makes the loop more stable.
  • Validate inputs: Always validate the tool name and arguments returned by the model. Return unknown tool names, missing required arguments and path traversal (..) to the model as error messages and let it retry.
  • Output length: Tool results consume context, so truncate them to a fixed number of characters.
  • Context length: Since the system prompt carries the tool declarations and the history, a context length of 8K or more is recommended.
