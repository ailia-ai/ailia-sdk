ailia LLM Tool Use Guide

How to use Gemma 4 function calling (tool use) with the ailia LLM Tool Use API: OpenAI-compatible tool definitions, returning tool results with the tool role, and parsing the output into structured data.

Overview

ailia LLM 1.5.0 and later provide a Tool Use (function calling) API. When tools are defined in OpenAI-compatible JSON, the tool declarations are rendered into the prompt through the model's chat template (llama.cpp) and the output is constrained by a grammar for the tool call syntax. The generated text can be converted into OpenAI-compatible tool_calls with ailiaLLMParseResponse, and tool results are appended to the history as messages with the tool role.

The declaration syntax, the tool call syntax and the embedding of tool results into the history are all handled by the chat template, so the application never has to build or parse Gemma 4 control tokens itself.

Note: The Tool Use API is available in ailia LLM 1.5.0 and later.

Supported Models

  • Gemma 4 E2B / E4B / 26B-A4B / 31B (GGUF)

Any model whose chat template supports tool calling can be used with the same API. The tool call syntax differs between models, but the declaration and the parsing are performed by the library according to the template.

Overall Flow

Tool use is a loop: the model emits a tool call, the application runs the tool and returns the result, and the model generates the final answer.

Defining Tools

Tools are defined in the same format as the tools parameter of the OpenAI Chat Completions API. parameters is a JSON Schema. The template converts the declaration into Gemma 4's <|tool>declaration:...<tool|> form, so there is no need to care about upper-case type names or the quoting notation.

[
  {
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "Get the current weather of a city.",
      "parameters": {
        "type": "object",
        "properties": {
          "city": {"type": "string", "description": "City name"}
        },
        "required": ["city"]
      }
    }
  }
]

While tools are set, the model output is constrained by a grammar for the tool call syntax. Missing quotes and malformed arguments are prevented at generation time, so format-error retries on the application side are normally unnecessary. Whether to call a tool is left to the model (equivalent to tool_choice: auto), and one tool call is emitted per response.

Generation and Parsing the Output

The text returned by ailiaLLMGenerate / ailiaLLMGetDeltaText is the raw model output including control tokens. When the model decides to use a tool, the output looks like this:

<|tool_call>call:get_weather{city:<|"|>Tokyo<|"|>}<tool_call|>

Passing the complete text of the generation to ailiaLLMParseResponse yields an OpenAI-compatible assistant message. arguments is a JSON string and id is call_0, call_1, ... in order of appearance within the message.

{
  "role": "assistant",
  "content": "",
  "tool_calls": [
    {"id": "call_0", "type": "function",
     "function": {"name": "get_weather", "arguments": "{\"city\":\"Tokyo\"}"}}
  ]
}

When thinking is enabled (ailiaLLMSetThinking), the reasoning is separated from content into reasoning_content. When no tool call is needed, tool_calls is absent and content is the final answer.

Returning Tool Results

After running the tool, append the following two messages to the history and call ailiaLLMSetPrompt.

  1. role: "assistant": the raw model output as is. The library parses it and re-renders the tool call according to the chat template.
  2. role: "tool": the tool result (plain text or a JSON string) as content, as is. It is matched to the tool calls of the preceding assistant message by order and the tool name is filled in automatically.

Gemma 4 has no tool role: the tool call and the result are placed in the same model turn as <|tool_call> and <|tool_response>. This conversion is performed by the chat template. Passing a tool message while no tools are set returns AILIA_LLM_STATUS_INVALID_STATE.

Sample Code

Python

import json
import ailia_llm

model = ailia_llm.AiliaLLM()
model.open("gemma-4-E2B-it-Q4_K_M.gguf", n_ctx=4096)

# 1. Tool definitions (OpenAI-compatible)
model.set_tools([{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Get the current weather of a city.",
        "parameters": {"type": "object",
                       "properties": {"city": {"type": "string"}},
                       "required": ["city"]},
    },
}])

def get_weather(city):
    return {"city": city, "weather": "sunny", "temperature_c": 25}

messages = [{"role": "user", "content": "What is the weather in Tokyo right now?"}]

while True:
    # 2. Generate (accumulate the raw output and append it to the history as assistant)
    raw = "".join(model.generate(messages))
    messages.append({"role": "assistant", "content": raw})

    # 3. Parse the output
    response = model.parse_response(raw)
    if not response.get("tool_calls"):
        print(response["content"])          # final answer
        break

    # 4. Run the tools and append the results to the history as tool
    for call in response["tool_calls"]:
        args = json.loads(call["function"]["arguments"])
        result = get_weather(**args) if call["function"]["name"] == "get_weather" else {"error": "unknown tool"}
        messages.append({"role": "tool", "content": result})   # a dict is serialized as JSON

model.set_tools(None)   # clear the tools

Implementation Notes

  • Precondition of ParseResponse: the parser is built when ailiaLLMSetPrompt is called, from the tool definitions and the thinking setting at that time. Before ailiaLLMSetPrompt, or after ailiaLLMSetTools / ailiaLLMSetThinking without a new ailiaLLMSetPrompt, it returns AILIA_LLM_STATUS_INVALID_STATE.
  • Pass the complete output: the text of an unfinished generation, or an output truncated by the context length, returns AILIA_LLM_STATUS_PARSE_ERROR. Do not use it while streaming; call it once after the generation is complete.
  • Keep the raw output in the history: put the raw output, not the result of ailiaLLMParseResponse, into the assistant history. The library parses and re-renders it, which also satisfies the Gemma 4 rules of removing the thinking of previous turns while keeping it within a turn that contains tool calls.
  • Streaming display: the text from ailiaLLMGetDeltaText contains control tokens such as <|tool_call> and <|channel>. Remove these blocks before displaying it.
  • Input validation: tool names are constrained to the defined ones, but argument values (e.g. paths) must be validated on the application side. Return errors as tool results in a tool message and let the model retry.
  • Context length: since the tool declarations, the history and the tool results are included in the prompt, a context length of 4K or more (8K or more for multi-round agents) is recommended. Truncate tool results to a fixed number of characters.
  • Clearing tools: call ailiaLLMSetTools(llm, NULL) when tools are no longer needed. After that, a history containing the tool role cannot be passed.
