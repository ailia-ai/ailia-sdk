ailia LLM MTP Benchmark

Measured results for Gemma 4 on the NPU and CPU of Qualcomm SoCs with MTP (Multi-Token Prediction) in ailia LLM 1.5.1.

For how MTP works and how to use it, see the ailia LLM MTP Guide. For QNN measurements without MTP, see the ailia LLM NPU (QNN) Benchmark.

  • Summary
  • Android (Snapdragon 8+ Gen 1 / SM8475, Snapdragon 7s Gen 3 / SM7635)
  • Windows (Snapdragon X Plus / SC8380XP)

Summary

  • With MTP, NPU text generation decode is 1.81x (SM8475), 1.55x (SM7635) and 1.71x (SC8380XP) for E2B, and 1.85x (SC8380XP) and 1.01x (SM7635) for E4B.
  • With MTP, CPU (4 threads) text generation decode is 0.94x (SM8475 E2B), 1.35x (SM7635 E2B), 1.65x (SM7635 E4B), 1.27x (SC8380XP E2B) and 1.68x (SC8380XP E4B).
  • For audio transcription, NPU decode with MTP is 1.66x to 2.91x.
  • On Android, comparing both with MTP, decode on the NPU is 1.12x the CPU for E2B on SM8475 and 0.87x for E2B on SM7635. Prefill on the NPU is 3.0x to 10.4x the CPU (2,048-token input), and image and audio input TTFT on the NPU is 1/1.9 to 1/6.9 of the CPU.
  • On SC8380XP, decode is fastest on the CPU, and the GPU drops to 0.50x to 0.59x with MTP. Prefill for inputs of 256 tokens or more is fastest on the NPU.
  • Prefill and TTFT are almost the same with and without MTP.

Android

Test Conditions

Results for Gemma 4 on two devices. Snapdragon 8+ Gen 1 (SM8475 / Hexagon v69) uses the E2B FP16 model, and Snapdragon 7s Gen 3 (SM7635 / Hexagon v73) uses the E2B / E4B Int16 models. The NPU main model and assistant are the v1.5.1 MTP models (W4), with QAIRT 2.47, a context length of 8192 and the AR-256 (prefill) / AR-4 (verification) / AR-1 configuration. Measured on 2026-10-12.

The CPU uses the llama.cpp path on the same device, with a GGUF main model (Q4_K_M for E2B, QAT Q4_0 for E4B) and a Q4_0 GGUF assistant. The main model, assistant and image / audio encoders all run with 4 threads. The QNN Benchmark was measured with 8 CPU threads on Android, so the CPU values differ.

For both CPU and NPU, "without MTP" runs without opening the assistant, and "with MTP" opens the assistant on the same main model (draft length 3). Each condition was measured twice in the order off → on → on → off, and the median time is shown. Each trial uses a new instance, with a 20-second gap between trials. TPS is computed from the time excluding the first output token. Sampling is greedy (temperature 0, top-k 1, top-p 1, seed 1234). The generated token sequences differ with and without MTP.

CPU usage is the process CPU time divided by the elapsed time and 8 cores, with all 8 cores fully used as 100%. Temperature and clocks were not fixed.

In the MTP curves, the time of each main-model run (round) is divided evenly among the tokens committed in that round. Rounds where many candidates are accepted show high TPS and rounds where all candidates are rejected show low TPS, so the values swing up and down. The TPS in the legend is computed from the total time.

Windows

Test Conditions

Results for Gemma 4 E2B / E4B on Snapdragon X Plus (SC8380XP / Hexagon v73, 8 cores) running Windows 11 Pro, measured in six configurations: CPU, GPU and NPU, each without and with MTP. Measured on 2026-10-13.

The CPU uses the llama.cpp path (OpenMP disabled, 4 threads), and the GPU uses the llama.cpp OpenCL backend on the Adreno X1-45, both with a QAT Q4_0 main model and a Q4_0 GGUF assistant (on the GPU, the assistant also runs on the GPU). The NPU uses the v1.5.1 MTP models (FP16 / W4). The image and audio encoders run on the CPU (BF16 mmproj GGUF) in the CPU and GPU configurations, and on the NPU in the NPU configurations.

Each configuration was measured once, with a 60-second wait before each trial. Context length 8192, greedy. The device was on AC power with the Balanced power plan and had background apps running. CPU usage is the process CPU time divided by the elapsed time and 8 cores. The QCS6490 MTP models have only been confirmed by an offline build, and performance has not been evaluated on a real device.
