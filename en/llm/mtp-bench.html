ailia LLM MTP Benchmark

Measured results for Gemma 4 on the NPU and CPU of Qualcomm SoCs with MTP (Multi-Token Prediction) in ailia LLM 1.5.1.

For how MTP works and how to use it, see the ailia LLM MTP Guide.

  • Android
    • Snapdragon 8+ Gen 1 (SM8475): E2B
    • Snapdragon 7s Gen 3 (SM7635): E2B / E4B
  • Windows
    • Snapdragon X Plus (SC8380XP): E2B / E4B
    • QCS6490: E2B

Android

Test Conditions

  • NPU: v1.5.1 MTP models (W4), QAIRT 2.47, context length 8192, AR-256 (prefill) / AR-4 (verification) / AR-1 configuration.
  • CPU: Runs with llama.cpp (4 threads). The main model is a GGUF (Q4_K_M for E2B, QAT Q4_0 for E4B) and the assistant is a Q4_0 GGUF.
  • MTP: "With MTP" opens the assistant (draft length 3). The acceptance rate is the fraction of assistant candidates accepted by the main model's verification.
  • Method: Greedy decoding, median of 2 runs per condition. Decode uses 81 input tokens and 1,000 generated tokens; prefill uses 64 to 2,048 input tokens and generates 1 token. Measured on 2026-10-12.
  • Image / audio input: One 768x768 image (100 output tokens) and a transcription of one English recording (32 output tokens). TTFT includes the encoder and excludes model opening.
  • CPU usage: Process CPU usage during decode, with all 8 cores fully used as 100%. The CPU runs 4 threads, so it stays around 50%.

Windows

Test Conditions

  • OS: Windows 11 Pro on SC8380XP, and Windows 11 IoT Enterprise LTSC on QCS6490.
  • NPU: v1.5.1 MTP models (FP16 / W4 on SC8380XP, Int16 on QCS6490), QAIRT 2.47, context length 8192.
  • CPU / GPU: The CPU runs with llama.cpp (OpenMP disabled, on the 4 performance cores), with a QAT Q4_0 main model and a Q4_0 GGUF assistant. The GPU uses the llama.cpp OpenCL backend on the SC8380XP Adreno X1-45 (not measured on QCS6490).
  • Method: Greedy decoding, one run per configuration. Decode, prefill and acceptance rate are defined as on Android. SC8380XP was measured on 2026-10-13 and QCS6490 on 2026-10-16.
  • Image / audio input: One 768x768 image (100 output tokens) and a transcription of one English recording (33 output tokens). The encoders run on the CPU in the CPU and GPU configurations, and on the NPU in the NPU configurations.
  • CPU usage: Process CPU usage during decode, with all 8 cores fully used as 100%. The CPU uses only the 4 performance cores, so it stays around 50%.
