ailia LLM NPU (QNN) Benchmark

Measured results of running Gemma 4 on the Qualcomm SoC NPU with the ailia LLM 1.5.0 QNN backend, compared with CPU execution on the same device.

For how to use the QNN backend, see the ailia LLM NPU (QNN) Guide.

MTP: This page shows results as of ailia LLM 1.5.0, without MTP. For results with MTP, see the ailia LLM MTP Benchmark.
  • Android
    • Snapdragon 8+ Gen 1 (SM8475): E2B
    • Snapdragon 7s Gen 3 (SM7635): E2B / E4B
  • Windows
    • Snapdragon X Plus (SC8380XP): E2B / E4B
    • QCS6490: E2B

Android

Test Conditions

  • NPU: QAIRT 2.47, context length 8192, AR-256 / AR-1 configuration.
  • CPU: The Q4_0 GGUF runs with llama.cpp on the same device (8 threads). "CPU" is the shipping configuration (OpenMP disabled), and "CPU (OpenMP)" is a comparison build with GGML_OPENMP=ON / OMP_NUM_THREADS=2.
  • Decode / Prefill: Decode uses 81 input tokens and 1,000 generated tokens; prefill uses 64 to 2,048 input tokens and generates 1 token.
  • Image / audio input: Medians over 10 images at 768x768 (100 output tokens each) and 10 FLEURS recordings. TTFT includes the encoder and excludes model opening.
  • CPU use: Process CPU use during a 2,048-token prefill, with all 8 cores fully used as 100%.

Memory usage

Memory usage while running the LLM, VLM and ALM configurations with 8 generated tokens (in MiB, context length 8192). The CPU path uses the Q4_0 GGUF with the BF16 mmproj, and the NPU path uses the Int16 QNN Model. Models are loaded with mmap, so anonymous memory (RssAnon, the working memory actually allocated) and file-backed mappings (RssFile, reusable page cache) are listed separately. Peak is the peak resident size of the process (VmHWM).

WorkloadPathVmHWMRssAnonRssFile
LLMCPU4574.21524.12896.5
LLMNPU (Int16)1666.8386.41276.2
VLMCPU4881.22512.440.3
VLMNPU (Int16)2161.2673.31483.7
ALMCPU4873.72623.01509.1
ALMNPU (Int16)2202.5591.61606.7
  • Anonymous memory on the NPU is about a quarter of the CPU path (0.25x for LLM, 0.27x for VLM, 0.23x for ALM), and peak resident size stays at 0.36x to 0.45x.
  • The CPU path expands all weights when the model is opened, taking 4,690.4 MiB, while the NPU path opens with 98.4 MiB and loads the compiled context on the first generate call. Between opening the model and the first generation it therefore holds about 1/48 as much.
  • Destroying the model returns both paths to about 87 MiB, and calling mallopt(M_PURGE, 0) brings it down to about 23 MiB.
  • The NPU values cover what is visible from the process; allocations that stay inside the DSP are not included. With only 8 generated tokens they also exclude the KV cache, which grows with longer inputs.

Windows

Test Conditions

  • OS: Windows 11 Pro on SC8380XP, and Windows 11 IoT Enterprise LTSC on QCS6490 (ailia LLM 1.5.0.1).
  • NPU: QAIRT 2.47, context length 8192, AR-256 / AR-1 configuration.
  • CPU / GPU: The CPU runs the Q4_0 GGUF with llama.cpp (OpenMP disabled, on the 4 performance cores). The GPU uses the llama.cpp OpenCL backend on the SC8380XP Adreno X1-45 (not measured on QCS6490).
  • Decode / Prefill / TTFT: Same conditions as Android.
  • Image / audio input: One 768x768 image (100 output tokens) and a transcription of one English recording, each measured once. On the CPU and GPU paths, the encoders run on the CPU.
  • CPU use: Process CPU use during a 2,048-token prefill, with all 8 cores fully used as 100%.
